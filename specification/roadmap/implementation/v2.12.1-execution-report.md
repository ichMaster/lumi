## Reconciled before the work (owner decisions, 2026-11-14)

- **The local proxy.** The roadmap's "the page speaks directly to the server, no server change" can't work, because
  the server sends no CORS headers. The owner chose a local proxy in the shell over CORS on the server or serving the
  page from the server.
- **`desktop/`, not `webview/`.** pywebview's import name is `webview`, so a `webview` package would shadow it.
- **The settings files, not `.env`.** `.env` was removed in v2.10.
- **The design is the owner's Claude Design handoff** (`design/v2.12/`), with **an English interface** (the owner's
  call after the handoff came back Ukrainian). Only her own words stay Ukrainian.

## Detailed Results

### LUMI-266 — the shell + the local proxy (#266)

`desktop/proxy.py` and `desktop/__main__.py`:
- **The settings.** The tree's `server.host` / `port` / `token` become an `Upstream`; the token is hidden from `repr`.
- **The local server.** A `ThreadingHTTPServer` on `127.0.0.1:0`:
  - it serves `desktop/ui/` and refuses any path outside it;
  - it templates a per-launch key into `index.html`;
  - it forwards exactly the eight `/v1` routes the page uses, adding `Authorization: Bearer <token>`;
  - only `Content-Type` / `X-Lumi-Client` / `Last-Event-ID` pass through to the server;
  - streams are relayed chunk by chunk.
- **Errors** reach the page as `{kind, detail}`: `no_server` 503, `unreachable` 502, `token_refused` 401.
- **The guard:** the key is required on `/v1`, the `Host` must be the proxy's own, no CORS header is sent, and
  OPTIONS is 405.
- **The shell:** pywebview is imported lazily; the window is 1200×800 (minimum 720×520); the proxy stops when the
  window closes.
- **Tests:** unit + integration against a fake server on loopback (the first SSE frame arrives while the server
  still waits) + the contract (`tests/contract/test_desktop_contract.py`).
- **Smoke:** against the real dev server, read-only, through the proxy.

### LUMI-267 — the page: the chat (#267)

`desktop/ui/`:
- **Assets:** `tokens.css` comes from the handoff with the system fonts only; `strings.en.json` holds every UI
  string.
- **What it shows.** It renders the chat column of the handoff at high fidelity:
  - messages, the "wrote first" marker and the source tags;
  - the thinking indicator and the block caret;
  - markdown built as DOM nodes, with links limited to http/https;
  - the command block, the dividers and the empty state (the mood of the day);
  - the input: the queue, the counter and the slash popover;
  - the status line: the DEV badge, the details panel, ⌘− / ⌘+;
  - the banners (connecting / unreachable with a live countdown / restored) and the token-refused and no-server
    screens.
- **The protocol** mirrors `tui/remote.py`:
  - a turn by `turn_id`, with the blocking fallback;
  - a 409 waits and retries;
  - `/v1/events` with `Last-Event-ID` and a 45 s dead-stream watchdog, backoff 5 / 10 / 15 / 30 s;
  - the page's own echoes skipped by `X-Lumi-Client`.
- **Found and fixed on the way:**
  - The SSE parser lost a last line that had no newline. It was checked with node against
    `tui.remote.parse_sse_frames` and now gives identical frames under any chunking.
  - A missing `stepsTitle` string, caught by the static test.
  - A stray "null" in the hints row, seen in the live window.
  - A duplicated line on a busy retry.
