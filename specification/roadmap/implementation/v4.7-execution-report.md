### LUMI-331: The dictation relay

**Status:** completed
**Commit:** ff9e402
**Files changed:** `server/dictation.py` (added), `voice/stream_stt.py`, `voice/stt.py`, `voice/dictator.py`,
`tests/unit/test_dictation_relay.py` (added), `tests/unit/test_stream_stt.py`.

- `relay(receive, send, setup)` runs one dictation. The client sends PCM (16 kHz mono int16) as binary frames and
  `{"type": "stop"}` / `{"type": "cancel"}` as text. The server answers `ready {mode}`, then `interim {text}` /
  `final {text}`, then `done`, or one `error {detail}`.
- **Stream mode** feeds the v1.6 `DeepgramStream`. The phrase hold of `UtteranceTracker` is kept, and the held part
  shows in the interim line. On a stop the relay sends `CloseStream` (the new `DeepgramStream.finish()`), waits up to
  3 s for the last results and then flushes the held phrase (`UtteranceTracker.flush()`), so nothing said is lost.
- **Batch mode** applies when there is no streaming recognizer or it can't open. The audio stays in memory and is
  recognized whole on the stop as a WAV (`voice.stt.wav_bytes`, now shared with the TUI's dictator).
- The caps: 5 minutes of audio, or of time, is treated as a stop; 10 s without an audio frame is an error. A cancel
  is silent, and a client that leaves ends it as `gone`.
- An error carries the exception type only. Nothing is written to disk. The log gets one line per dictation:
  `dictation: <mode>, <s> s of audio, <n> chars, <outcome>`, never the words.

**Validation:** 15 relay tests and 2 stream-STT tests pass, with a fake stream and a fake batch STT; ruff clean.

- The WebSocket checks the owner token before it accepts. A room token, a wrong token or a server without a

### LUMI-333: The shell's side

**Status:** completed
**Commit:** 4e69a8e
**Files changed:** `desktop/dictation.py` (added), `desktop/proxy.py`, `desktop/__main__.py`, `pyproject.toml`,
`uv.lock`, `tests/unit/test_desktop_dictation.py` (added), `tests/contract/test_desktop_contract.py`,
`tests/integration/test_desktop_proxy_flow.py`.

- `Dictation` runs one dictation per window. It connects to `/v1/dictation` with the client token and opens the
  Mac's mic (`sounddevice`, 16 kHz, on `dictation.stt_device`) only after the server's `ready`.
- A sender thread sends the blocks in order, emits a `level` (the peak, 0..1, about ten a second), applies the
  5-minute cap and sends `stop` after the last block.
- A stop, a cancel, an error, the cap and the window's close all close the mic. A page that goes away (a reload)
  cancels the dictation.
- The proxy serves four local routes behind the window's key, never forwarded: `GET /local/dictation`
  (`{available, reason}`), `POST /local/dictation/start` (an SSE stream; 409 busy, 503 unavailable),
  `POST /local/dictation/stop` and `POST /local/dictation/cancel`. `Proxy.stop()` cancels a running dictation.
- The desktop extra gained `sounddevice` and `websockets`.

**Validation:** 13 unit tests with a fake mic and a fake socket; the proxy contract test; an integration test from
the page's route through a real uvicorn server to the words coming back; ruff clean.

### LUMI-334: The window

- The mic button sits in the composer before Send. A click toggles a recording; a hold longer than 350 ms talks
  while held; ⌥Space does both.
- A live line under the input shows the level, the status, an mm:ss timer and the phrase being spoken (muted).
  Each settled phrase is appended to the input after whatever is there, so it can be edited before sending.
- Esc cancels and restores the input as it was before the recording. An error restores it too and shows one line
  for 8 s.
- «Send when I stop» is a checkbox in the hints, remembered in `localStorage`. With it on, the text is sent as soon
  as the recording ends.
- The button is shown only when the shell can record and the server has a recognizer.

**Validation:** 7 static tests; an end-to-end run in headless Chrome against the real proxy with a fake mic and a
fake recognizer (the click toggle with live words, level and timer; a final appended after typed text; Esc restores
the input; a ⌥Space hold stops on release; an error restores the input with a line; «Send when I stop» sends; the
mic opened 5 times and closed 5 times; no files left); ruff clean.

## Deviations

- The phrase being spoken is shown in a muted live line under the input, not inside the input: a textarea can't
  style part of its text. Only settled phrases enter the input.
- Settled phrases are appended to the input's current value, so typing during a recording is kept.
- The batch fallback lives in the server's relay, not in the shell: the shell always streams, and the server decides
  how to recognize.
