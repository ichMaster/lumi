# v2.4 — Issues

Issues for phase **v2.4 — Pushes & state: the API a face can live on** (version **v2 — Client/server split:
her brain on the server, the TUI a thin client**), derived from the Tasks and DoD in
[ROADMAP.md](../../ROADMAP.md) §v2.4 and the contracts in [ARCHITECTURE.md](../../ARCHITECTURE.md). This
file covers one phase; ids continue from the previous phase (LUMI-218 → **LUMI-219…222**).

The server learns to **speak first**: a long-lived push channel (`GET /v1/events`, Server-Sent Events —
the SSE choice of v2.3) carries a **per-turn face event** `{emotion, intensity, theme}`, the **state
snapshot whenever it changes** (mood, closeness level, style, model/profile, theme) and **surfaced
thoughts**. The client's status line then lives on pushes alone. Typed `%directives` come back to client
mode — they run **on the server** and their surfaced thought is pushed to every connected client, so a
thought fired from `./lumi-cli` arrives in the TUI unasked. The automatic thought sources (idle thinking,
the scheduler, ticks) still move in v2.5.

**Design note (owner, 2026-10-10).** The ROADMAP's DoD asks for "a surfaced thought arriving unasked", but
nothing on the server produces thoughts until v2.5. The owner chose to bring **`%directives` to the
server** now (`POST /v1/directive`, the same `run_directive`): typed directives work in client mode again,
and `./lumi-cli think` is the honest unasked source for the DoD. Also folded in: the v2.2 review's deferred
**#7** (a torn `/v1/state` mid-turn) — state is now published **from the turn's runner, under the lock**.

## v2.4 — Pushes & state: the API a face can live on

### LUMI-219 — The push channel — GET /v1/events: the face event per turn + state on change

**Description:**
`server/app.py`: an in-process **event bus** (one queue per subscriber) and `GET /v1/events`, a long-lived
SSE stream every connected client listens to. The server publishes the face event after each turn and the
state snapshot whenever it changes.

**What needs to be done:**
- The bus: `subscribe()` → a bounded queue; `publish(event, data)` → every subscriber (a full queue drops
  its oldest, never blocks the publisher); unsubscribe when the stream closes.
- `GET /v1/events` (token): SSE frames `event: <name>` + JSON `data`; a `:` **heartbeat** comment every
  ~15 s (keeps the connection honest, gives the server a cancellation point); the first frame is the current
  `state` (a fresh client is in sync at once).
- Events:
  - `turn` — `{emotion, intensity, theme}` after **every** turn (streamed or blocking) — the face signal over
    the wire; no image, no path, a theme **name** only.
  - `state` — the full snapshot, published when it **differs** from the last published one: after turns,
    commands, session switches, and when the background mood finishes at start. Built **in the turn's
    runner / under the service lock** (closes v2.2 review #7 — no torn snapshot mid-turn).
- The state gains `closeness` `{level, name}` (the level by name only — the raw value stays internal).
- Every request may carry `X-Lumi-Client: <id>`; events caused by it carry `origin` = that id (`null` for
  server-originated) — a client can tell its own echoes from the rest.
- Docs: ARCHITECTURE §Contracts — the events route, the event set, `origin`, `closeness` in the state, **no
  face assets on the API** (theme names only).

**Dependencies:** None

**Expected result:**
A connected client hears every turn's face state and every state change without asking.

**Acceptance criteria:**
- [ ] `GET /v1/events` streams the current `state` first, then `turn` after each turn and `state` only on
  change; heartbeats flow; the token is required
- [ ] Two subscribers both receive; a disconnected one is dropped; a slow one never blocks a turn
- [ ] The `state` published around a turn is consistent (built under the lock); `closeness` is present
- [ ] `origin` matches the requesting client's id; server-originated events carry `null`
- [ ] **Tests:** the bus (fan-out, bounded drop, unsubscribe); the events route via `TestClient` streaming
  against a mock-model core (first state, a turn → `turn` + `state`, an unchanged command → no `state`);
  no network, no paid API
- [ ] **Contract:** the API contract extended (route set, event names + `turn` fields, `closeness`, the
  `origin` rule) + **no route returns an image / no event carries a path** + ARCHITECTURE
- [ ] **Gates:** `ruff` + `pytest`

### LUMI-220 — Directives on the server — POST /v1/directive + the thought push + `lumi-cli think`

**Description:**
`server/app.py`: run a typed `%directive` on the server with the core's `run_directive` and push its
surfaced thought to every listener; `cli/main.py`: a `think` subcommand that fires one.

**What needs to be done:**
- `POST /v1/directive {line}` (token, the one-at-a-time lock): `run_directive(line, session)` →
  `{is_directive, mode, thought{kind, text, emotion, when}?, saved_to?}`; not a directive → `is_directive:
  false` (the client then treats the line as chat, as in-process).
- An **open** thought (`mode == "open"`) is published as `thought` `{kind, text, emotion, when, origin}`; a
  silent one isn't (it's in `/thoughts`); `state` publishes if the directive changed it.
- `./lumi-cli think [topic]` → `%think! [topic]` through the route; prints the thought — and every
  connected TUI receives it **unasked** (the DoD's source).

**Dependencies:** LUMI-219

**Expected result:**
A thought fired anywhere reaches every connected client.

**Acceptance criteria:**
- [ ] A typed `%think!` returns its thought and publishes one `thought` event with the requester's `origin`
- [ ] A silent `%think` publishes no `thought`; a non-directive returns `is_directive: false`
- [ ] `lumi-cli think` prints the thought and a second subscriber receives it
- [ ] **Tests:** the route + the push (a mock-model core, a second subscriber), the CLI subcommand over a
  `TestClient` transport; no paid API
- [ ] **Contract:** the route in the API contract + ARCHITECTURE
- [ ] **Gates:** `ruff` + `pytest`

### LUMI-221 — The client lives on pushes — a listener with reconnect, status + thoughts from events, %directives back

**Description:**
`tui/remote.py` gains a background **listener** on `/v1/events` (reconnecting with backoff);
`tui/app.py` applies the events — the status line and the stats from `state`, surfaced thoughts as `💭` —
and typed `%directives` run through the server again.

**What needs to be done:**
- `RemoteCore.listen(on_event)` / `stop()`: a daemon thread streaming `/v1/events` (the v2.3 SSE parser);
  `state` events update the snapshot; every event goes to `on_event`; a drop → reconnect with backoff (1 s →
  30 s max), a readable note once per outage, back-in-sync on reconnect (its first `state`).
- Each `RemoteCore` sends its id as `X-Lumi-Client`; a `thought` whose `origin` is its own id is skipped (the
  requesting client renders it from the response) — never shown twice.
- `RemoteCore.run_directive(line, session)` → `POST /v1/directive` → a `DirectiveOutcome`-shaped result, so
  the TUI's **existing** `%directive` path runs unchanged; the v2.2 "`%directives`: not yet in server mode"
  gate goes away (the idle thought-stream stays off until v2.5).
- `tui/app.py` (client mode): start the listener on mount (stop on exit); `on_event` marshals to the UI
  thread — `state` → re-render the status/stats; `thought` → the same `💭` line as in-process open
  thoughts; `turn` → nothing extra (the face is the viewer's; the status already updates from `state`).

**Dependencies:** LUMI-220

**Expected result:**
`./lumi-client` updates its status line from pushes alone and shows a thought fired from elsewhere,
unasked.

**Acceptance criteria:**
- [ ] A state change made by another client (e.g. `lumi-cli model …`) appears in the TUI's status line with
  no TUI request
- [ ] A thought fired from another client appears as `💭 …` unasked; the TUI's own `%think!` shows once
- [ ] A dropped events stream reconnects with backoff and resyncs; no traceback, no duplicate lines
- [ ] Typed `%directives` work in client mode again; the idle thought-stream still says "not yet"
- [ ] **Tests:** the listener over a fake streaming transport (events → callback, a drop → reconnect, own-
  origin skip); the TUI pilot in client mode: a pushed `state` re-renders the status, a pushed `thought`
  renders once, `%think!` through the server; no network
- [ ] **Contract:** the `RemoteCore` surface pin still holds (the TUI's core surface ⊆ `RemoteCore`)
- [ ] **Gates:** `ruff` + `pytest`
