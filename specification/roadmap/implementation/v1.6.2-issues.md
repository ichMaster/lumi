## LUMI-199: The talking register — a voice-mode reply config in core

### Description

Voice mode answers through the same `Core.reply()` as text — but on a **talking register**: the
voice-tuned reply configuration the probes measured (llm-first ~0.8 s). No second brain, no second
memory path — one mind, different register.

### What needs to be done

- A `voice` **role** in the model profiles (`core/models.toml` `[profiles.*]`, default
  `gemini-2.5-flash` for the gemini profile; env override `LUMI_MODEL_VOICE`) — the same
  role-resolution path as `think`/`mood`/`housekeeping`.
- A **register switch** on the reply turn (plumbed from the TUI per-turn, not global env): when the
  turn runs on the talking register — (a) the reasoning/inner-voice directive is **omitted** from
  the system prompt (the probe's `LUMI_REASONING=off` effect, scoped to the turn); (b) the reply
  model is the profile's `voice` tier; (c) the reply is requested as the **streamed structured**
  `{reply, emotion, intensity, intent}` (the existing v1.4 `reply_structured_stream` seam — the
  emotion contract is UNTOUCHED); (d) Gemini calls carry the core's permissive `safetySettings`
  and thinking OFF (both already core behavior — pinned for the voice tier by a test).
- Everything else stays the reply turn's normal path: closeness read, RAG, memory writes, the v1.5
  async post-turn queue, the v0.3 validation gate.
- Contract tests: register off (default) → **byte-identical** prompt + model; register on → no
  reasoning directive in the system prompt, the voice model resolved, `{reply, emotion, intensity}`
  still validated (mock model, no paid calls).

### Dependencies

None (first in the phase; builds on shipped v1.4 streaming + v1.5 async POST).

### Expected result

`Core.reply()` can run one turn on the talking register: fast voice-tuned prompt + model, full
memory/emotion semantics, zero change when the register is off.

### Acceptance criteria

- [ ] `voice` role resolves from models.toml / `LUMI_MODEL_VOICE` (gemini default `gemini-2.5-flash`)
- [ ] Talking-register turn: no think directive in the system prompt; voice tier used; streamed structured reply
- [ ] Emotion contract validated exactly as text mode (contract test)
- [ ] Memory writes + async queue + per-user isolation unchanged (existing tests stay green)
- [ ] Register off → byte-identical (pinned by test); `pytest` + `ruff` pass; no paid CI

## LUMI-200: Streaming STT adapter — Deepgram WS + the phrase-hold tracker in /voice

### Description

Promote the probe's streaming-STT half into the `/voice` package as a tested adapter: Deepgram WS
recognizes DURING speech; its endpointing (plus the phrase-hold) decides the end of the turn.

### What needs to be done

- `voice/stream_stt.py`: `build_deepgram_url(...)` (linear16 16 kHz mono, `language=uk`,
  `interim_results`, `endpointing` — default 500 ms, env `LUMI_VOICE_ENDPOINT_MS`,
  `utterance_end_ms=1000`, `smart_format`) and the **`UtteranceTracker`** — moved from
  `scripts/chain_ws_probe.py` verbatim with its semantics: finalized segments accumulate;
  **an un-punctuated `speech_final` is HELD** for the continuation or the `UtteranceEnd` backstop;
  empty finals ignored; no double-flush.
- An async `DeepgramStream` seam: connect (key from `DEEPGRAM_API_KEY`), send pcm frames, yield
  parsed events — with an **injectable transport** so tests feed scripted `Results`/`UtteranceEnd`
  dicts (no network, no paid CI). Interim events are exposed (LUMI-201's barge-in needs "he is
  speaking now" while she plays).
- The probe script switches to importing these from `/voice` (one source of truth; the probe stays
  the manual harness).
- Unit tests: URL shape, tracker (hold/join/backstop — port the probe's tests), scripted-transport
  round-trip.

### Dependencies

None (parallel with LUMI-199).

### Expected result

`/voice` owns a tested streaming-STT adapter; the probe and the TUI loop share it.

### Acceptance criteria

- [ ] `voice/stream_stt.py` with `build_deepgram_url` + `UtteranceTracker` + `DeepgramStream` (injectable transport)
- [ ] Phrase-hold semantics pinned by tests (un-punctuated hold → join; `UtteranceEnd` backstop; no double-fire)
- [ ] `scripts/chain_ws_probe.py` imports from `/voice` (no duplicated tracker)
- [ ] `pytest` + `ruff` pass; no network/paid calls in tests

## LUMI-201: Streaming TTS output + barge-in — sentence-streamed ElevenLabs in /voice

### Description

The speaking half: the reply's streamed prose goes sentence-by-sentence into ElevenLabs (her
voice) and out the speaker — and **she stops when interrupted** (the owner-requested barge-in).

### What needs to be done

- `voice/stream_tts.py`: the ElevenLabs **stream** endpoint adapter (`pcm_24000`, her
  `LUMI_VOICE_ID` + `LUMI_VOICE_MODEL`, `voice_settings_for` bias; stdlib urllib, chunked read) —
  promoted from the probes; injectable/mocked in tests (no paid CI).
- The **speaker pipeline**: the lossless lock-protected byte buffer + `sounddevice` output callback
  (the probes' proven shape), a sentence queue (synth serialized off the reply stream), and the
  guards before TTS: `clean_sentence` + the **`speakable`** Latin-vs-Cyrillic gate +
  `StreamTagFilter` on the streamed reply (promoted from `scripts/chain_probe.py` into `/voice`).
- **Barge-in** (the v1.6.2 rule): a Deepgram **interim** (from LUMI-200's stream) arriving while
  the speaker buffer is non-empty → clear the buffer + drop the queued sentences + abandon the
  un-spoken tail — **playback only, never the committed turn** (the `Message` keeps the full
  reply text; what she *audibly* said may be a prefix).
- Unit tests: sentence queue order, the gates in the path, barge-in clears buffer+queue exactly
  once and never cancels the turn (scripted events, mock TTS).

### Dependencies

- LUMI-200 (the interim events feed the barge-in trigger).

### Expected result

A tested `/voice` speaking pipeline: streamed reply → her voice, with working barge-in.

### Acceptance criteria

- [ ] `voice/stream_tts.py` + the speaker pipeline with the lossless buffer (mock TTS in tests)
- [ ] `StreamTagFilter` + `clean_sentence` + `speakable` guard the TTS path (pinned by test)
- [ ] Barge-in: interim-while-playing → buffer + queue cleared, committed turn untouched (contract test)
- [ ] `pytest` + `ruff` pass; no paid CI

## LUMI-202: /mode-set voice — the in-TUI live loop, degradation, docs

### Description

Wire it together: `/mode-set text|voice` in the TUI, the in-process live loop (mic → LUMI-200 →
`Core.reply()` on the LUMI-199 register → LUMI-201 → speaker), every failure degrading to text.

### What needs to be done

- `LUMI_MODE_SET` (default `text`) + the `/mode-set text|voice` command (session-local, like
  `/model`); status bar shows `mode:voice`; `voice/live.py` hosts the loop (asyncio WS +
  `sounddevice` in the Textual event loop — no separate process; headphones documented, no AEC).
- Turn flow: committed utterance (tracker flush) → printed as the user line → **exactly one
  `Core.reply()`** (talking register) → the streamed reply renders in the TUI **and** speaks via
  LUMI-201; the per-turn stage line (endpoint / llm first / tts first) in the status or log.
- **Typed input + slash commands keep working** in voice mode (the keyboard path is untouched).
- **Degradation:** missing keys (`DEEPGRAM_API_KEY`/`ELEVENLABS_API_KEY`/`LUMI_VOICE_ID`), WS
  drop, TTS failure, silent mic → a readable text-mode line + fall back to `mode: text`; never a
  dead TUI, never a lost turn.
- Config into `.env.example`; VOICE_MODE.md / TELEGRAM-style operator notes updated;
  `LUMI_MODE_SET=text` → **byte-identical** pinned by test.
- Integration test with the fake Deepgram transport + mock TTS + mock model: one spoken turn
  end-to-end (utterance → one reply → sentences queued), plus the byte-identical-off contract.

### Dependencies

- LUMI-199, LUMI-200, LUMI-201.

### Expected result

`/mode-set voice` gives a live spoken conversation with Лілі — her voice, full memory/persona —
inside the existing TUI; off by default and byte-identical when off.

### Acceptance criteria

- [ ] `/mode-set text|voice` + `LUMI_MODE_SET` (default text) + status-bar surfacing
- [ ] Live loop: one `Core.reply()` per committed utterance; reply both rendered and spoken
- [ ] Typed input + slash commands still work in voice mode
- [ ] Every failure degrades to a readable text line + text mode (tests per failure class)
- [ ] `LUMI_MODE_SET=text` → byte-identical (contract test); `.env.example` + VOICE_MODE.md updated
- [ ] Full `pytest` + `ruff` green; no paid CI
