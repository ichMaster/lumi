## Findings

### 1 — 🟠 MEDIUM — no read timeout towards the server

`desktop/proxy.py:104` builds its client with `httpx.Timeout(connect=5, read=None, …)`, and the page has no timeout on a
turn. The TUI client gives a turn 600 s and the push channel 45 s (`tui/remote.py`, `LISTEN_READ_TIMEOUT_S`). This
breaks in two ways.

**Scenario A — a push stream stalls.** The network drops without a reset, or the server freezes, so no heartbeat comes.
1. After 45 s the page's watchdog aborts and reconnects. The proxy only learns the page has gone when it next writes.
2. Its thread stays blocked in `iter_raw()` on a server that never sends. One thread and one socket leak per attempt,
   for as long as the stall lasts.

**Scenario B — a turn hangs on the server** (the ~8-minute hang class).
1. The window shows "answering" with no end; the input only queues.
2. The TUI, against the same hang, prints a readable line after 600 s.

**Fix:** per-route read timeouts that mirror the TUI — 45 s on `/v1/events`, 600 s on everything else. A stalled read
then ends the relay (`ReadTimeout` is a `TransportError`), so the thread is freed. For a turn, the page then takes its
blocking `turn_id` fallback, and in the end "The reply was cut off · Retry".

### 2 — 🟡 LOW — the busy retry repeats its note forever

`desktop/ui/app.js` `turn()` → `busy()` adds "She is answering another conversation — your line waits" and retries in
3 s, on every 409, for as long as another client holds her lock.

**Scenario:** a long `%learn` runs on the server for 60 s, and the chat gets 20 identical notes.

**Fix:** show the note once per line; the retries stay silent.

### 3 — 🟡 LOW — the page can be framed

`desktop/proxy.py` `_static` sends neither `X-Frame-Options` nor a `frame-ancestors` policy. A page in the owner's
browser can scan loopback ports and frame `http://127.0.0.1:<port>/`. That page is the real chat, with its key, and
another origin can't script it — but it can overlay it (clickjacking a "Retry now" or a typed line).

**Fix:** `X-Frame-Options: DENY` + `Content-Security-Policy: frame-ancestors 'none'` on every page response. The
pywebview window loads the page at the top level, so nothing changes for it.

### 4 — 🟡 LOW — a malformed `Content-Length` crashes the handler

`desktop/proxy.py` `_forward`: `int(self.headers.get("Content-Length") or 0)` raises `ValueError` on `abc`.
`socketserver` then prints a traceback and drops the connection without an answer. A negative length is let through as
"no body".

**Fix:** a non-integer or negative length → `400 {"kind": "bad_request"}`.

### 5 — 🟡 LOW — another OS user can borrow the proxy

The key is in the HTML that `GET /` serves to anyone who can reach `127.0.0.1:<port>`. A browser can't read that
cross-origin response, which is the point of the key. But another OS account on the same Mac can read it with `curl`,
then call `/v1` as the owner. `secrets.yaml` is `0600`, so that account couldn't read the token itself.

**Home: backlog.** The Mac is single-user. The fix is to hand the key to the page through pywebview's `js_api`
instead of the HTML.

### 6 — 🟡 LOW — the window's process gets every setting

`desktop/__main__.py` calls `load_config()`, which exports the resolved settings into `os.environ`, as the server and
the TUI need. The window needs only `server.host` / `server.port` / `server.token`, but holds the provider API keys in
its environment too.

**Home: cleanup.** Read the three values without exporting (`load_config(load_env=False, settings_dir=…)`).

### 7 — 🟡 LOW — the wait shows no inner voice

The owner noticed this live: a reply on dev (`gemini-3.1-pro-preview`, thinking on) takes about 11 s before the first
character. The TUI fills that time with the streamed `think` text; the window reads those frames and drops them.

**Home: v2.12.2**, whose think block already shows them.

## What's solid

- **The token never reaches the page.** Only `Content-Type` / `X-Lumi-Client` / `Last-Event-ID` cross to the server,
  and only `Content-Type` / `Cache-Control` come back. Errors are the proxy's own `{kind, detail}`; the contract test
  pins this.
- **The guard order is right.** The `Host` is checked before anything, so even the page itself refuses a rebinding
  name. The key is compared in constant time. No CORS header is sent, and OPTIONS is 405.
- **The page can't inject HTML.**
  - Every node is built.
  - Markdown links match only `https?://` and are set with `setAttribute`.
  - A static test bans every HTML sink.
- **The turn protocol is the TUI's.** A broken stream asks the same `turn_id` the blocking way, so she never answers
  twice. The SSE parser gives the same frames as `tui.remote.parse_sse_frames` under any chunking (checked with node).
- **Packaging is contained.** pywebview is lazy and optional, and stays out of the server image (pinned).
