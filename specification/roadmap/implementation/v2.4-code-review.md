## Findings

### 1. 🟠 The daily mood is computed twice on a racing start

**Anchor:** `core/agent.py::_ensure_mood`.
**Scenario (live, 2026-10-11):** `./lumi-server` starts → `_background("mood", …)` begins today's mood call
(~30 s on gemini-2.5-flash). The owner's first message arrives meanwhile → `core.reply` → `_ensure_mood`
sees no mood yet and no logged reading (the log is written only after the call) → a **second** mood call.
The dev log shows two `mood 2026-10-11` readings at 01:35:59 and 01:36:02 (two `mood` entries in the cache
log, 1154 input tokens each). Whichever finishes last wins `Core.mood`, so the startup push carried reading
#1 and the turn reading #2 — the resolution, and possibly the face theme, flip within seconds. The same race
exists in-process (the mount worker vs a quick first message).
**Fix:** single-flight — a lock around the check-and-compute; a second caller waits for the first and
reuses its reading (it would have waited for its own call anyway).

### 2. 🟡 A taken port wastes the startup and misleads

**Anchor:** `server/__main__.py::main`.
**Scenario (the owner hit it):** port 8766 was held by another project's server → the banner "Lumi server on
http://127.0.0.1:8766 … — Ctrl+C to stop" printed, the core was built and the background mood call
started, then uvicorn failed with `[Errno 48] … address already in use` and the process exited mid-call.
**Fix:** check the port before building the core — one readable line naming the port and how to find its
holder; no model call, no banner.

### 3–7. Deferred

- **3 (v2.5):** with #1 fixed nothing in v2.4 runs a housekeeping model call beside a turn; v2.5 brings the
  scheduler/ticks/thoughts into the server — they must take the turn lock (the v2.3 review's note) or pass
  thinking per call instead of flipping the shared client.
- **4 (backlog):** turns run the tool loop (which re-asks) whenever any tool is on; a tool-less streamed reply
  is rare. Mirror the single-call re-ask in `_stream_single` when it shows up.
- **5 (backlog):** tell 401 apart in the listener ("the server rejected the token — restart the client").
- **6 (v4):** fine for one owner and a face client; many users want an async `asyncio.Queue` route.
- **7 (backlog):** a lost directive response is already an error line in the requester; the thought stays in
  `/thoughts`.

## What's solid

- **Pushes never hold a turn:** bounded per-listener queues, drop-oldest, the publisher never blocks (a stuck
  listener test).
- **A listener never holds the stop:** the first Ctrl+C closes the bus; the real-uvicorn test fails on plain
  uvicorn.
- **No torn state:** every snapshot is taken under the turn lock; `GET /v1/state` mid-turn returns the last
  consistent one (closes v2.2 #7).
- **No face asset on the API:** the `turn` event carries the validated emotion and a theme *name* (pinned).
- **Never twice on screen:** own thoughts are skipped by `origin`; an outage is said once; a reconnect resyncs
  from its first `state`; an older server (404) ends the listener quietly.
- **The Gemini re-ask is bounded:** one extra call, only when an answer is empty, both calls counted, the
  reason logged; the regression tests fail on the old code.
