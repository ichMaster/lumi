## Findings

### 1 — 🟠 The split drag rebuilds the right panels on every move ([desktop/ui/app.js](../../../desktop/ui/app.js), `sidePanel`)

**Scenario.** Both right panels are pinned, say Files in each, one showing a picture page or a reader with an inline
picture. The owner drags the rule between them. The pointer-move handler sets `vw.split` and calls `renderSide()`,
which `replaceChildren`s the column. That has two effects:

1. **It refetches the pictures.** Every move re-mounts both views: `releaseBlobs` drops the pictures and refetches
   them. Her pictures are about 1.4 MB each, so a two-second drag pulls tens of megabytes over the LAN, and the panels
   flicker.
2. **It breaks the drag.** The split handle holding the pointer capture is itself replaced. A captured element taken
   out of the document loses its capture, so the drag stops after the first move.

The keyboard path (↑ ↓) calls `renderSide()` too: it doesn't break, but it re-mounts and refetches on every step.

**Fix.** Apply the split in place. A small `applySplit()` sets the two sections' `flex` from `vw.split`. Neither the
drag nor the keys rebuild the column, so the handle and its capture survive and the views stay mounted.

**Test.** A static pin: the split's drag and key handlers call `applySplit()` and never `renderSide()`. Also a live
check in headless Chrome: the panel bodies are the same nodes after a split change.

### 2 — 🟡 A NUL byte in `path` is a 500 ([core/browse.py](../../../core/browse.py) `_resolve`)

**Scenario.** `GET /v1/files?path=%00`. `safe_path` resolves `Path("\x00")`, `os.path.realpath` raises
`ValueError: embedded null byte`, and `_browse` maps only `BrowseError` and `OSError`. The answer is a bare 500 with a
traceback in `lumi.log`, where it should be a readable 400. Only the owner's token reaches the route, so this is
robustness, not exposure.

**Fix.** `_resolve` maps a `ValueError` from the guard to `BadPath("a malformed path")`.

**Test.** A unit test (`read_text` / `list_folder` / `read_picture` with `"a\x00b"` → `BadPath`) and a contract test
(each route with `%00` → 400).

### 3 — 🟡 The page doesn't read `features.files` ([desktop/ui/app.js](../../../desktop/ui/app.js) `renderViews`)

**Scenario.** `DESKTOP_VIEWS.md` and ARCHITECTURE say a client shows only the views the server serves
(`GET /v1/state.features`). The page always shows Files. Against a server without the routes — an older server, or
one with no sandbox configured — the tab opens onto "Couldn't open lili/ · 404". The same holds for a pinned Files
panel.

**Fix.** The page shows a view only when the state says so:
- Chat is always shown; Files only when `features.files === true`.
- An unknown state (before the first push) hides Files.
- A served-set change re-renders the row and the panels, and moves an open view that is no longer served back to
  Chat.

It re-renders only when the set changes: a state push arrives after every turn, and must not re-mount the panels.

**Test.** A static pin: `served()`, the row and the panels built from the served views, and `syncServed` re-rendering
only on a change. Also a live check: a state without `features.files` hides the tab, and `files: true` shows it.

### 4 — 🟡 Typed by the head (deferred)

`list_folder` types a file as text when its first 4 KB are NUL-free UTF-8. A file that turns binary later
(rare in her sandbox: her tools write UTF-8 text) is listed as text and opens to a readable 415 error. Typing the whole
file would read up to 1,000 files fully per listing. **DEFER → backlog**: the error state is honest, and the cost of a
full read isn't worth it.

### 5 — 🟡 Non-UTF-8 file names (deferred)

On Linux a file name with bytes that aren't UTF-8 comes back as a `str` with surrogate escapes, and JSON encoding it
fails with a 500. Her tools create UTF-8 names; such a file could only come from a copy by hand. **DEFER → backlog**:
the fix is to skip such names or show them replaced, and nothing produces them today.

## What's solid

- **One sandbox guard.** Every path goes through `safe_path`; a symlink out is neither listed nor read; a second
  user's folder is unreachable (contract-tested with two cores). Errors name the sandbox path only.
- **Read-only by construction.** No write call in `core/browse.py`; the fingerprint tests cover core and the routes.
  The routes never take the turn lock, and the test holds the lock while reading.
- **Pictures** are typed by magic bytes. SVG and HTML are never served as pictures. `nosniff` and `inline` reach the
  page through the proxy. The page loads pictures only through `fetch` with the key into `blob:` URLs, and releases
  them per place.
- **The reader builds DOM nodes**, never HTML, and no `<a href>` at all: an external link is text plus its address,
  and a link out of the sandbox is text. `resolveIn` is checked under node.
- **The room's token** gets 403 on every new route (contract-tested).
