# v2.12.2 — Issues

Issues for sub-phase **v2.12.2 — The face & state panel** of phase **v2.12 — pywebview client: chat + face in one
window** (version **v2 — the server platform**), derived from the Tasks and DoD in [ROADMAP.md](../ROADMAP.md) §v2.12,
the contracts in [ARCHITECTURE.md](../ARCHITECTURE.md) and the owner's design in
[design/v2.12/](../../../design/v2.12/). Released as `2.12.2`; ids continue from v2.12.1 and its addendum
(LUMI-270 → **LUMI-271…275**).

The second half of the desktop window: her portrait beside the chat, switching with each reply's emotion. Then the
caption, theme and closeness; the mood of the day; the think block that fills the wait with her inner voice; the
quiet-thoughts strip; and the narrow layout's portrait strip. All of it follows the Claude Design handoff, with no
server change.

**Reconciled with the real code (2026-11-14):**
- **The face is picked in the shell, served locally.** The roadmap asks for the portrait to be picked by "the
  existing `viewer.face.face_for`". The v0.11 wardrobe resolver is `viewer.face.resolve_variants`: it walks
  theme → emotion, with the theme's `calm` and the default theme as fallbacks, then the flat v0.7 pack. The window
  reuses it in the Python shell.
  - The local proxy gets two routes of its own, never forwarded: `GET /face?theme&emotion&intensity` → `{src}`, and
    `GET /faces/<path>` → the PNG from the client's own pack (`viewer.faces_dir`, default `viewer/faces`).
  - No face crosses the network.
- **By intensity** (the owner's decision, 2026-11-14). The packs name each emotion's three files by intensity (`01`
  mid, `02` low, `03` high — the `place-faces` skill), and the design maps intensity to them. The window picks that
  way: low → `02`, mid → `01`, high → `03`. A folder that doesn't name its files so falls back to the random
  no-repeat pick (`viewer.face.pick_variant`). The old viewer stays as it is.
- **Inline pictures are deferred** (the owner's decision, 2026-11-14). A picture she sends (v0.24 `send_image`) only
  goes into the server's Telegram outbox, and the server offers it to no API client. Showing it needs a server route +
  a push field — a server change this client-only sub-phase doesn't make. Home: the v4.3 web client, which needs the
  same route. Pictures keep arriving in Telegram.
- **The replay is flagged.** Replayed `message` / `thought` events carry `"replay": true` (`server/app.py`,
  `_REPLAYABLE`). The v2.12.1 page guessed the replay by timing; the strip's unread state and the messages' times use
  the flag.
- **The interface stays English.** The theme names, the closeness names (Polite … Dearest), the captions and the
  thought kinds come from `desktop/ui/strings.en.json`. Her own words stay Ukrainian.

## v2.12.2 — The face & state panel

### LUMI-271 — The face pick in the shell: `/face` + `/faces/` on the local proxy, by intensity, from the client's own pack

**Description:**
A new `desktop/faces.py` (pure) and two local routes on `desktop/proxy.py`. The page asks the proxy which portrait
goes with a state; the shell answers from the client's own face pack. Nothing goes to the server.

**What needs to be done:**
- **`desktop/faces.py` — `FacePicker(faces_dir, default_theme, rng)`:**
  - `pick(theme, emotion, intensity)` → a path relative to `faces_dir`.
  - The folder comes from `viewer.face.resolve_variants`: theme → emotion → the theme's `calm` → the default theme →
    the flat v0.7 image.
  - Inside a folder whose files are `01.png` / `02.png` / `03.png`, intensity chooses: the band from
    `viewer.face._band` (< 0.34 low, < 0.67 mid, else high) → `02` / `01` / `03`.
  - Any other folder falls back to `viewer.face.pick_variant`: random, no immediate repeat (it remembers the last pick).
  - An unknown emotion → `calm`; an unknown theme → the default theme.
  - The default theme is `viewer.themes.load_themes(faces_dir).default`.
- **The proxy** (`Proxy(faces_dir=…)`; the shell passes `load_config().faces_dir`):
  - `GET /face?theme=…&emotion=…&intensity=…` → `200 {"src": "/faces/<rel>", "theme", "emotion", "band"}`. It needs
    the launch key and the proxy's own `Host`, like `/v1`.
  - `GET /faces/<rel>` → that PNG from `faces_dir`. A path outside it, or not a `.png`, is 404. It needs the `Host`
    but no key — an `<img>` can't send headers, and the portraits never leave this machine.
  - With no pack (`faces_dir` missing), `/face` → `404 {"kind": "no_faces"}` and the page shows no portrait.
- Neither route is ever forwarded to the server: `FORWARDED` is unchanged.

**Dependencies:** None

**Expected result:**
For any `(theme, emotion, intensity)` the shell names one portrait of the local pack, and the page can load it from
`127.0.0.1`.

**Acceptance criteria:**
- [ ] By intensity in a `01/02/03` folder; the random no-repeat pick otherwise; the fallback chain to calm, the
      default theme and the flat image.
- [ ] `/face` answers `{src}`; `/faces/` serves only PNGs under `faces_dir`.
- [ ] Neither route reaches the server; both need the proxy's `Host`, and `/face` the key.
- [ ] **Tests:**
  - unit (`tests/unit/test_desktop_faces.py`) over a generated tmp pack: the bands, the fallback chain, no repeat,
    an unknown emotion and theme;
  - integration — the proxy's `/face` + `/faces/` against a tmp pack: traversal, a non-PNG, no key, a foreign `Host`,
    the fake server sees no request;
  - contract (`test_desktop_contract.py`) — face files never ride `/v1`: `FORWARDED` unchanged, `/faces/` rooted in
    the pack.
- [ ] **Gates:** `ruff`, `pytest`.

### LUMI-272 — The portrait panel: the portrait with its crossfade, the caption, theme + closeness, the mood of the day; the narrow strip

**Description:**
`desktop/ui/` gains the handoff's portrait panel (`<aside>`, `width: clamp(300px, 36%, 440px)`, a 2px rule) beside the
chat, and the narrow layout's top strip below 760 px.

**What needs to be done:**
- **The portrait:**
  - A 1:1 box with **two stacked layers (A/B)**. A new portrait loads into the hidden layer, then the opacities swap
    in 480 ms. There is no layout jump.
  - It is driven by:
    - the state's `last_emotion` + `theme` on connect;
    - each `turn` push (`{emotion, intensity, theme}`);
    - each turn's `done` payload.
  - The page asks `/face` for each and skips the swap when `src` is unchanged.
- **The caption:** `800 28px/1.08`, `aria-live="polite"`, from `strings.en.json` `captions` — never the emotion's name.
- **The meta grid:**
  - **Theme of the day:** the English name + `slug · scene` (from `themes`).
  - **Closeness:** the English name by level (Polite … Dearest), "N of 5" and the 5-cell meter
    (`role="img" aria-label="Closeness N of 5"`).
- **The mood of the day:**
  - folded to 2 lines, with "Expand ▾ / Collapse ▴" (`aria-expanded`, the chevron turns in 200 ms);
  - the text is `lang="uk"`;
  - updated by every `state` push.
- **The empty state** (a new session): the panel shows the portrait + caption only, and the chat shows the mood of the
  day large (v2.12.1).
- **The narrow layout (< 760 px)** — the panel becomes the top strip:
  - a 52×52 thumb with the same crossfade; tapped, it expands to a full-width square (max 420 px) with a 44 px
    collapse button;
  - the caption at 18 px;
  - the meta line "Close · 4/5 · Quiet Collapse";
  - the mood row folded to 1 line;
  - a 44×44 thoughts button with the unread badge (wired by LUMI-273).
- `prefers-reduced-motion` turns the crossfade off.

**Dependencies:** LUMI-271

**Expected result:**
Her portrait sits beside the chat and changes with each reply's emotion, theme and intensity. Around it: the caption,
the theme, the closeness and the mood of the day, in the handoff's layout at both widths.

**Acceptance criteria:**
- [ ] A turn's emotion crossfades the portrait and the caption; a theme change in a `state` push changes the pack;
      a push from another client (`turn`) does too.
- [ ] Theme / closeness / mood follow the `state` pushes; the mood expands and folds.
- [ ] The narrow strip below 760 px: the thumb, the expand, the meta line, the mood row.
- [ ] Every string from `strings.en.json`; no HTML sink.
- [ ] **Tests:** static (`test_desktop_static.py`):
  - the panel's strings exist;
  - the portrait's two layers and the 480 ms transition;
  - the caption never takes the raw emotion name;
  - `/face` is the only portrait source;
  - no HTML sink.
  - Rendering is LUMI-275's manual check.
- [ ] **Gates:** `ruff`, `pytest`.

### LUMI-273 — The think block (her inner voice during the wait) + the quiet-thoughts strip

**Description:**
`desktop/ui/` shows the `think` frames the v2.12.1 page dropped, and the `thought` pushes in the strip under the
mood.

**What needs to be done:**
- **The think block** (above her reply):
  - The `think` frames stream into it as they arrive, so the ~11 s the owner noticed on dev shows her inner voice;
    the turn's `done.thinking` fills it when nothing streamed.
  - Three modes, from the details panel's "Inner voice" `.seg`:
    - **shown:** the header with `chevron-down` + the text at 14 px in `--l-faint`;
    - **collapsed:** one line — `chevron-right` + "Inner voice" + the first words;
    - **hidden:** not rendered.
  - Clicking a block's header flips that one message; the override is cleared when the global mode changes.
  - The mode is kept in `localStorage`. The first default comes from the state's `think_show`: `open` → shown,
    `debug` → collapsed, `off` → hidden.
  - Replayed and pushed lines have no think block (it comes only with this window's own turns).
- **The quiet-thoughts strip** (under the mood; the handoff's option 1b):
  - Each `thought` push (`{kind, text, emotion, when}`) is one item: an unread square, the kind's English label
    (`thoughtKinds`, an unknown kind as is), the time, the text (`lang="uk"`) and the emotion's caption.
  - The items go newest first. Folded, the strip shows the newest one, "1 new" / "N new" and "All · N"; expanded, it
    shows all of them, with "Collapse".
  - Unread is cleared when the strip is closed after opening.
  - Replayed thoughts (`replay: true`) are never unread.
  - In the narrow layout the cloud button opens the same list inside the strip.
- **The replay flag:** messages and thoughts use `data.replay` instead of the v2.12.1 timing guess.
  - A replayed message gets no time.
  - The "While offline · N" divider counts only replayed lines after a reconnect.

**Dependencies:** LUMI-272

**Expected result:**
While she thinks, the window shows her inner voice. Her quiet thoughts gather beside the portrait without ever
entering the chat.

**Acceptance criteria:**
- [ ] `think` frames stream into the block; the three modes and the per-message override work; the mode persists.
- [ ] A `thought` push lands in the strip (unread, counted), never in the chat; a replayed one is not unread.
- [ ] The missed-lines divider and the times follow the `replay` flag.
- [ ] **Tests:** static:
  - the think path reads `think` frames;
  - the three modes and the `think_show` mapping;
  - thoughts never call the chat's row builders;
  - the `replay` flag is used;
  - the new strings exist.
- [ ] **Gates:** `ruff`, `pytest`.
