# v3.4 — Issues

Issues for phase **v3.4 — Her initiative: she opens a line in Agora when she wants** (version **v3 — Agora: the room
as a channel of her own**), derived from the Tasks and DoD in [ROADMAP.md](../../ROADMAP.md) §v3.4, the agora space
API v2 ([`docs/agora-space-api.json`](../../../docs/agora-space-api.json), `"version": 2` since sync step 10) and
[ARCHITECTURE.md](../../ARCHITECTURE.md) §Spaces / §Contracts. This file covers one phase; ids continue from the
previous phase (LUMI-295 → **LUMI-296…300**).

v3.4 lets her start a line of her own in Agora:
- the bridge polls `GET /v1/initiative` while its room rules allow; a poll never calls the model;
- the space composes one offer on demand, in the background, on a client of its own, under its own guards;
- the bridge acks what it posted (`POST /v1/initiative/{initiative_id}/posted`), and only then is the text her line;
- the server serves the agora space API v2 (`AGORA_API = 2`, health `"agora": 2`); one switch, `agora.initiative`
  (off).

It builds on v3.1–v3.3's room path (`core/space.py` `AgoraSpace`, `state/space_store.py`, the server's room routes),
the v3.2 space recipe (`build_prompt`, the room rule, the name guard) and v3.3's hourly cap. Then dev runs `v3.4.0`
with the initiative on: step 12's end, and CR12. The live test is step 14 (G7); prod is step 15 (G8).

**Reconciled with the code (2026-11-16):**
- The contract file is already v2 (`a9937b1`); the server still serves v1 (`server/app.py` `AGORA_API = 1`), and
  `tests/contract/test_agora_server_contract.py` skips the three v2 examples (`V2_ONLY`) while `AGORA_API < 2`.
- ARCHITECTURE §Spaces has the initiative as "Planned (v3.4)"; §Contracts names v2 as led by the file.
- `AgoraSpace._take_a_call` updates the cap's call list without a lock: the room turn is its only caller today. A
  background compose makes it a second caller, so the cap gains a lock (LUMI-297).
- The room's prompt (`build_prompt`) is pinned by the space-recipe and sentinel tests. The initiative's prompt reuses
  the recipe's parts; the turn's prompt stays byte for byte.

### LUMI-296 — The offer record and its table in the room's store

**Description:**
An initiative offer is kept in the room's own store, beside its lines, until it is acked or 24 h old. Files:
`core/space.py` (the record and the `SpaceStore` seam) and `state/space_store.py` (the table).

**What needs to be done:**
- `SpaceOffer{channel, initiative_id, text, composed_at, last_seq, stats, emotion, intensity, event_id}` in
  `core/space.py`. `composed_at` is ISO-8601 with its offset. `last_seq` is the room's newest line at composing.
  `event_id` stays `None` until the ack.
- The `SpaceStore` seam gains:
  - `add_offer(offer)`;
  - `get_offer(channel, initiative_id)`;
  - `latest_offer(channel)`, the newest by `composed_at`;
  - `ack_offer(channel, initiative_id, event_id) -> bool`, which sets `event_id` only when it is still `None`;
  - `prune_offers(channel, before_ts)`, which drops offers composed before `before_ts`;
  - `last_seq(channel) -> int`, the highest line `seq` of the space (0 when empty). `seq` is `AUTOINCREMENT`, so
    any new line raises it and a removal never does.
- `SqliteSpaceStore`: a `space_offers` table keyed by `(channel, initiative_id)`, created with the others
  (`CREATE TABLE IF NOT EXISTS`, so an existing `spaces.sqlite` gains it on start). An offer row that no longer
  reads is skipped.
- Nothing of his: no `user_id`, the room's file only.

**Dependencies:** None

**Expected result:**
The room's store keeps offers by id, acks each one once, and drops them after their time.

**Acceptance criteria:**
- [ ] An offer round-trips. `latest_offer` returns the newest. `ack_offer` is true once, then false, and false for an
  unknown id. `prune_offers` drops only the old ones.
- [ ] `last_seq` grows with every new line (an observed line, her reply, an acked offer) and never falls back to a
  reused value after a removal.
- [ ] An existing room store (v3.3's schema) opens and gains the table, and its lines are untouched.
- [ ] **Tests:** unit, `tests/unit/test_space_store.py`, on a temporary SQLite file.
- [ ] **Gates:** `ruff`, `pytest`.

### LUMI-297 — Composing an offer: the poll, the background compose, the guards, the initiative instruction

**Description:**
`AgoraSpace.poll_initiative()` answers a poll without a model call. It returns a fresh offer as it is. When there
is none and the guards allow, it starts one compose in the background on the room's initiative client. The prompt
is the space recipe plus an authored initiative instruction. Files: `core/space.py` and a new
`core/agora_initiative.md`.

**What needs to be done:**
- `AgoraSpace` gains:
  - `initiative: bool = False` (off → every poll is `none`, with no compose);
  - `initiative_llm` (the room's client for composing; defaults to the housekeeping client, a separate instance on
    the server, so its stats never mix with a turn's and a compose never holds the turn lock);
  - code constants matching the contract's `limits`: `INITIATIVE_FRESH_S = 1800`,
    `INITIATIVE_COMPOSE_GAP_S = 1800`, `INITIATIVE_KEPT_S = 86400`.
- `poll_initiative() -> InitiativeOffer | None`, where `None` means `none`. It never calls the model:
  - **Returns** the latest offer when all of these hold: it is not acked; it is fresh
    (`now - composed_at < INITIATIVE_FRESH_S`); it is not stale (`store.last_seq == offer.last_seq`; a new room line
    since composing makes it stale at once).
  - **Otherwise it starts one background compose only when all the guards allow:**
    - the initiative is on;
    - no compose is in flight;
    - the last compose attempt was at least `INITIATIVE_COMPOSE_GAP_S` ago. Every attempt counts: an empty one, a
      guarded one and a failed one.
    - the room's last line (by `ts`) is not hers (never twice in a row);
    - the hourly cap has room (the compose takes a call; a full cap means no compose and no attempt counted).
  - It then answers `none`. Offers older than `INITIATIVE_KEPT_S` are pruned on the way.
- **The compose** runs on a daemon thread, in this order:
  1. Record `last_seq` at the start.
  2. Build the prompt. The system part is the space recipe (the canon, the room rule, her day, the room's gists,
     today's digest, recall over the room with the last room lines as the query) plus the initiative instruction.
     The user part is the room's window as one quoted transcript; when the room is empty, a line saying so.
  3. Make one `reply_structured` call through the emotion gate.
  4. Apply the guards before an offer exists. Each of these means no offer, logged («initiative held: <reason>»):
     an empty reply; Gemini's «…»; a reply naming him (the name guard); any «Ich».
  5. Otherwise store a `SpaceOffer` with `initiative_id = "ini-" + 12 hex`.
  6. Log the call in `cache-log.jsonl` as `kind: "agora"`.
  7. Any error is logged and leaves no offer. A compose never raises into a poll.
- **The recipe refactor:** the shared sections (canon, rule, day, gists, digest, recall) come from one helper used by
  both `build_prompt` and the compose. **The turn's prompt stays byte for byte** (the recipe and sentinel tests are
  unchanged). As on a turn, nothing of his is reachable from the compose, and her thoughts' text stays out.
- `core/agora_initiative.md` (authored, Ukrainian, `#` comment lines) says:
  - she may open a line in Agora if she wants to, with something of hers (her day) or a thread of the room's talk,
    today's or earlier;
  - never about «Ich» or their talks alone;
  - never a question to anyone by name;
  - short, in her own voice;
  - if she has nothing, she leaves `reply` empty.
- **The cap gains a lock:** `_take_a_call` is shared by the turn thread and the compose thread.
- `close()` waits for a compose in flight (bounded, as for a turn).

**Dependencies:** LUMI-296

**Expected result:**
A poll answers at once. After a quiet stretch she has an offer of her own ready, and the guards decide when she may
compose one.

**Acceptance criteria:**
- [ ] A poll never calls the model (a fake client's call count stays 0 across polls); the first poll starts a compose
  and answers `none`; a later poll gets `say`.
- [ ] Guards: off → `none`, no compose; a compose in flight → `none`, no second; the gap holds a second attempt (an
  empty answer waits too); her line last → no compose; a full cap → no compose; a compose counts in the cap (a turn
  after it sees the call).
- [ ] The name guard and «Ich» → no offer, logged; an empty reply / «…» → no offer.
- [ ] Freshness: past 30 min → `none` and a new compose may start (after the gap); a new room line → stale at once.
- [ ] A turn's prompt is byte for byte as before; the compose's prompt has the recipe and the instruction, never his
  data (the sentinel kept out).
- [ ] **Tests:** unit, `tests/unit/test_agora_initiative.py`, with fake room clients (counting, holding, failing), an
  injected clock and monotonic. No network, no paid calls.
- [ ] **Gates:** `ruff`, `pytest`.

### LUMI-298 — The ack: an offer the room saw becomes her line

**Description:**
`AgoraSpace.initiative_posted(initiative_id, event_id)`: the bridge posted the offer, so its text becomes her line
in the room's session, embedded for recall. Never acked means never remembered. File: `core/space.py`.

**What needs to be done:**
- Under the state lock, in this order:
  - An unknown (or pruned) id → `False`.
  - An offer already acked → `False`.
  - A `lili` line with that `event_id` already stored → `False`.
  - Otherwise:
    - store `SpaceMessage(role="lili", speaker="Лілі", source_id=event_id, text=offer.text, ts=now, emotion,
      intensity)` in the session of `now`;
    - embed it;
    - mark the offer acked;
    - return `True`.
- An ack after the offer went stale for polling is honoured (the room saw it).
- His side needs no new code. As a `lili` line in the room's session it reads «Лілі: …» in «Агора сьогодні» and «в
  Агорі, Лілі: …» in his recall (v3.3.1's labels).

**Dependencies:** LUMI-297

**Expected result:**
What the room saw of her initiative is in her memory of the room, once. What it never saw is not.

**Acceptance criteria:**
- [ ] The ack stores her line once (idempotent; a second ack → `False`). A late ack (stale offer) stores it. An
  unknown id → `False`. An unacked offer leaves no line and no vector.
- [ ] After the ack, the room's last line is hers: the next poll composes nothing (never twice in a row), and her
  line appears in the next room turn's window as «Лілі (ти)».
- [ ] His recipe shows it as hers: «Агора сьогодні» «Лілі: …», his recall «в Агорі, Лілі: …».
- [ ] **Tests:** unit (`tests/unit/test_agora_initiative.py`) and the owner-recipe test
  (`tests/unit/test_owner_agora_recipe.py`), with fake models.
- [ ] **Gates:** `ruff`, `pytest`.
