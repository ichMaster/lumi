## Detailed Results

### LUMI-327: The voice of her lines on the server

**Status:** completed
**Commit:** 507b2f4
**Files changed:** `server/voice.py` (added), `server/__main__.py`, `server/app.py`, `server/brain.py`, `state/bus.py`,
`tests/unit/test_server_voice.py` (added).

- `VoiceSwitch` keeps the switch in `<data root>/voice.json` (`{"enabled": bool}`, written through a temp file and a
  rename). Its first value is `telegram.voice`. It is `available` only with the ElevenLabs key and a voice id;
  turning it on without them raises `VoiceUnavailable`.
- `VoiceStore` keeps the files at `<data root>/voice/<user_id>/<32 hex>.mp3`, written through a temp file and a
  rename. A link or a malformed name is never read. `expire` removes files older than 30 days and stale temp files,
  at most 500 per pass, one folder level, no links.
- `LineVoicer` is one ordered worker and the server's **only** outbox writer:
  - while the switch is on, each of her lines is voiced once, after the line is shown, and its outbox record carries
    `voice: "<id>.mp3"` (or `null` when the voicing failed);
  - while it is off, the record carries `voice: null` and no TTS call is made;
  - any other write (your mirrored line, a photo) goes straight to the outbox when nothing is queued, otherwise it
    waits behind the line still being voiced, so the outbox order is the order of the lines;
  - a text over 3000 characters is cut at a sentence end before it is voiced;
  - each voicing is logged as `voice: made <id> (<n> chars, <ms> ms)` or `voice: failed <id> (<type>: <message>)`,
    never with the text.
- The server's turn, inbox and spoken-thought paths and the Telegram photo sink all write through it.

**Validation:** 22 unit tests pass (TTS faked, the clock injected); ruff clean.

### LUMI-329: Telegram sends the stored file

**Status:** completed
**Commit:** 6b2c51c
**Files changed:** `telegram/outbound.py`, `docs/TELEGRAM_SETUP.md`, `tests/integration/test_voice_tags_flow.py`,
`tests/unit/test_telegram_outbound.py`, `tests/unit/test_telegram_photo.py`.

- `delivery(record, voice_mode)` decides per record: a photo, a stored file, an old record, a skip, or text.
  - A record with a stored file goes as a voice message (MP3 → OGG through ffmpeg) and never calls TTS.
  - A record with `voice: null` goes as text.
  - A record without the `voice` key (written before v4.6 or by the in-process TUI) goes the old way: voiced by the
    daemon in voice mode, text otherwise.
- `forward(...)` replaces `voice_to_telegram`; the daemon makes a TTS client only in voice mode with a key.

**Validation:** the ported and the new unit tests pass; the integration flow passes; ruff clean.
