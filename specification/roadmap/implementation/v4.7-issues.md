# v4.7 — Issues

Issues for phase **v4.7 — Dictation in the window** (version **v4 — The window: her files, pictures, journal and
thoughts in Lili.app**), derived from the Tasks and DoD in [ROADMAP.md](../../ROADMAP.md) §v4.7 (the owner,
2026-11-19) and the contracts in [ARCHITECTURE.md](../../ARCHITECTURE.md). This file covers one phase; ids continue
from the previous phase (LUMI-330 → **LUMI-331…334**).

v4.7 lets the owner dictate in the window:
- a mic button in the composer (hold to talk, or click to start and stop; ⌥Space; Esc cancels);
- the words appear in the input while they speak, and stay there to edit before sending (or go by themselves with
  «Send when I stop»);
- the window's Python shell records the Mac's mic, the server recognizes the audio with the box's key over an
  owner-only WebSocket, `/v1/dictation`;
- without the streaming recognizer the recording is recognized whole when it stops.

It builds on the v1.6 streaming recognizer (`voice/stream_stt.py`), the v0.26 batch adapter (`voice/stt.py`) and its
device resolution (`voice/dictator.py`), the server's owner guard, and the window's key-guarded local routes (v4.5).
The TUI's dictation is unchanged. This is the last phase of v4.

**Reconciled against the code (2026-11-19):**
- **The streaming recognizer:** `voice/stream_stt.py`:
  - `build_deepgram_url(model=, lang=, rate=16000, endpoint_ms=500, utterance_end_ms=1000)` (linear16 mono, interim
    results, smart_format, endpointing);
  - `UtteranceTracker.feed(event) -> str | None` joins `is_final` segments and holds an unpunctuated `speech_final`
    until the continuation or `UtteranceEnd`. It has **no public flush**: the parts still held when a recording stops
    are reachable only through `_flush()`;
  - `DeepgramStream(api_key, url=, _connect=)` with `open`, `send_pcm` (drops frames into a dead socket), `events()`
    (skips non-JSON) and `close`. It has **no way to tell Deepgram the audio ended** (Deepgram's
    `{"type": "CloseStream"}` text message), so the last phrase would be lost on a stop.
  - The real path lazy-imports `websockets`. The image installs every extra but `dev` and `desktop`: on 2026-11-19 both
    box instances had `websockets 16.0`, `uvicorn 0.54.0`, `stt_provider deepgram`, `stt_model nova-2`, `stt_lang uk`
    and a Deepgram key (read-only check). uvicorn serves WebSockets through `websockets`.
- **The batch recognizer:** `voice/stt.py` `build_stt(provider, api_key=, model=)` → `DeepgramSTT` (REST, `urllib`,
  30 s timeout), `ElevenLabsScribeSTT`, `WhisperSTT` or `MockSTT`; `recognize(audio, *, lang, content_type)`.
  `telegram/inbound.py` builds it with `cfg.deepgram_api_key or cfg.elevenlabs_api_key`. The WAV wrapper is
  `voice/dictator.py` `_wav(pcm, rate)` (private, `pragma: no cover`).
- **The settings:** `dictation.*` in `core/config.py`: `dictation` (the TUI's dictator), `stt_provider`,
  `stt_model`, `stt_lang`, `stt_device` (a device index or a name substring, resolved by
  `voice.dictator.resolve_input_device`), and `deepgram_api_key` in the secrets. No new setting is needed: the
  server reads its own `stt_*`, the window's shell reads its own `stt_device`.
- **The server:** the owner guard is `require_token` (a `Header` dependency; the room's token → 403) used as
  `guarded`. `state_snapshot` builds `features` (`files`, `gallery`, `journal`, `schedule`, `actions`, …) and v4.6
  added `voice` at the top level. No route is a WebSocket yet; FastAPI's `TestClient.websocket_connect` takes headers.
- **The window's shell and proxy:** `desktop/__main__.py` builds `Proxy(upstream_from(cfg), faces=, emoji=)` and runs
  pywebview; `proxy.stop()` runs when the window closes. The proxy's local routes are `LOCAL_ROUTES =
  ("/local/save", "/local/reveal", "/local/open")`: the window's key, the `Host` check, POST only, never forwarded,
  pinned by `tests/contract/test_desktop_contract.py`. The page reads a streamed body with its `sse()` helper
  (`/v1/events`, `/v1/turn/stream`).
- **The Mac's environment:** `./lumi-desktop` runs `uv run --extra desktop`, and the `desktop` extra holds only
  `pywebview`. `sounddevice` and `websockets` are in the `dictation` / `realtime` extras. The prod client is synced
  with `--all-extras` (`scripts/prod_update.py`), but the dev launcher would need them in `desktop`.
- **Design:** the v4 brief and handoff (`design/v4/`) have no dictation; the window's tokens and icons are reused.

## v4.7 — Dictation in the window

### LUMI-331 — The dictation relay: PCM in, `interim` / `final` / `error` / `done` out

**Description:**
The recognition half of `/v1/dictation`, as a module the route only wires: it takes the owner's audio frames and
control messages, runs the streaming recognizer (or, without it, the batch one at the end), and yields the text
messages the window shows. New `server/dictation.py`; small additions to `voice/stream_stt.py`.

**What needs to be done:**
- `voice/stream_stt.py`:
  - `UtteranceTracker.pending() -> str` (the held parts joined, for the interim line) and `flush() -> str | None`
    (the held parts as one final, used at the end of a recording);
  - `DeepgramStream.finish()` sends `{"type": "CloseStream"}`, so Deepgram returns the last results and closes.
- `server/dictation.py`:
  - `DictationSetup(stt, stream_factory, lang)`: the batch recognizer (`build_stt`), an `async () -> DeepgramStream`
    factory or `None` (no streaming: not Deepgram, no key, no `websockets`), and `stt_lang`;
  - `async relay(receive, send, setup, *, clock, max_s=300, idle_s=10)`: `receive()` gives the client's frames (bytes
    = PCM 16 kHz mono int16; text = `{"type": "stop"}` or `{"type": "cancel"}`), `send(msg)` takes the messages:
    - `{"type": "ready", "mode": "stream" | "batch"}` first;
    - `{"type": "interim", "text"}`: the phrase being spoken (the tracker's held parts + the current interim segment),
      replaced by the next one;
    - `{"type": "final", "text"}`: a settled phrase (the tracker's output, the phrase hold kept);
    - `{"type": "error", "detail"}`: a readable line, then the end; the window leaves the input as it was;
    - `{"type": "done"}`: after a stop, once the last final is sent;
  - stream mode: each PCM frame goes to `send_pcm`; the events feed the tracker; on stop, `finish()`, read the
    remaining events (bounded, ~3 s), `flush()` the tracker, `done`;
  - batch mode (no factory, or the stream fails to open): the PCM is kept **in memory only** (≤ 5 minutes ≈ 9.6 MB),
    wrapped as WAV on stop and recognized once (`asyncio.to_thread`), then one `final` (if not empty) and `done`;
  - cancel: close the stream, nothing more is sent, the buffer dropped;
  - the caps: 5 minutes of audio → treated as a stop; no frame for 10 s → `error` ("no audio") and the end; a
    recognition error (the stream breaks, the batch call raises) → `error` with the exception's type, never its
    text if it could carry the audio;
  - nothing is written to disk; the log gets one line per dictation (mode, seconds, characters, how it ended), never
    the text.
- Move the WAV wrapper into `voice/stt.py` as `wav_bytes(pcm, rate)` (the dictator keeps calling it).

**Dependencies:** None

**Expected result:**
A tested relay that turns the owner's audio into `interim` / `final` / `done` messages with the box's recognizer, or
fails with one readable `error`.

**Acceptance criteria:**
- [ ] Stream mode with a fake `DeepgramStream`: interim → final text, an unpunctuated pause held and joined, the held
  phrase flushed on stop, `CloseStream` sent on stop.
- [ ] Batch mode with `MockSTT`: one recognition of the whole recording on stop, the WAV header right, an empty result
  → `done` without a `final`; a stream that fails to open falls back to batch.
- [ ] The caps: 5 minutes → stop; 10 s without a frame → `error`; cancel → no message after it; a recognition error →
  one `error`.
- [ ] No file is written (the relay is given no path); the log line holds no text.
- [ ] **Tests:** `tests/unit/test_dictation_relay.py` (fake stream, `MockSTT`, injected clock — no network, no paid
  call); the tracker's `pending` / `flush` and `finish` in `tests/unit/test_stream_stt.py`.
- [ ] **Gates:** `uv run ruff check .`, `uv run pytest -q`.

**What needs to be done:**
- `create_app(..., dictation: DictationSetup | None = None)`.
- `@app.websocket("/v1/dictation")`:

- ARCHITECTURE §Contracts: a "v4.7 (additive) — dictation" paragraph (the route, the frames, the messages, the

**Acceptance criteria:**

- [ ] A second dictation while one runs gets `busy`; the turn lock is never taken (a turn runs meanwhile).
- [ ] `features.dictation` true with a recognizer, false without; the state otherwise byte-identical.
- [ ] **Contract:** the route set and the message shapes pinned in `tests/contract/test_server_api_contract.py`;

### LUMI-333 — The shell's side: the Mac's mic, the WebSocket, the local routes

**Description:**
The window's Python shell records the mic and streams it to the server; the page drives it through local routes.
New `desktop/dictation.py`; `desktop/proxy.py`, `desktop/__main__.py`, `pyproject.toml` (+ `uv.lock`),
`tests/contract/test_desktop_contract.py`.

**What needs to be done:**
- `desktop/dictation.py` `Dictation(upstream, *, device, open_mic, connect, clock)`:
  - `open_mic(device, callback)` defaults to a `sounddevice.RawInputStream` (16 kHz, mono, int16, ~100 ms blocks) on
    `dictation.stt_device` (`resolve_input_device`); `connect(url, token)` defaults to the `websockets` sync client
    on `ws://<server>/v1/dictation` with `Authorization: Bearer <token>`. Both are injectable;
  - `start(emit)`: one at a time; connect first, then open the mic only after the server's `ready`; each block goes
    to the socket and gives a `level` event (0..1 peak, at most ~10 a second); the server's messages are passed to
    `emit` as they come;
  - `stop()` sends `{"type": "stop"}` and closes the mic at once, then waits for `done` / `error`; `cancel()` sends
    `{"type": "cancel"}`, closes the mic and the socket, and emits nothing more;
  - the mic is closed on stop, cancel, an error, the 5-minute cap and `close()` (the window closing); the socket
    closes after `done`, `error` or cancel;
  - no audio is kept: blocks go straight to the socket.
- `desktop/proxy.py`, behind the window's key and the `Host` check, never forwarded:
  - `GET /local/dictation` → `{available, reason}` (the shell can record: `sounddevice` and `websockets` importable,
    a server configured);
  - `POST /local/dictation/start` → a streamed `text/event-stream` of `ready`, `level`, `interim`, `final`, `error`,
    `done` until the end (409 while one runs);
  - `POST /local/dictation/stop`, `POST /local/dictation/cancel`;
  - `Proxy.stop()` cancels a running dictation, so closing the window closes the mic.
- `pyproject.toml`: the `desktop` extra adds `sounddevice` and `websockets`, so `./lumi-desktop` can record.

**Dependencies:** LUMI-332

**Expected result:**
The page can start, stop and cancel a dictation and read its words and level, while the shell holds the mic only
during a recording.

**Acceptance criteria:**
- [ ] With a fake mic and a fake socket: the mic opens after `ready` and is closed on stop, cancel, an error, the cap
  and `close()`; blocks reach the socket; `level` events are throttled.
- [ ] Stop sends `stop` and relays the last `final` and `done`; cancel emits nothing after it.
- [ ] The local routes: without the key 403, a foreign `Host` 403, GET on a POST route 405, a second start 409;
  `/local/dictation` says why it is unavailable.
- [ ] Closing the proxy cancels a running dictation.
- [ ] **Tests:** `tests/unit/test_desktop_dictation.py`; the local routes' key guard and the route set in
  `tests/contract/test_desktop_contract.py`; an integration test through the proxy against the server app with a fake
  stream (`tests/integration/test_desktop_proxy_flow.py`). No mic, no network, no paid call.
- [ ] **Gates:** `uv run ruff check .`, `uv run pytest -q`.

### LUMI-334 — The window: the mic button, the live words, Esc, «Send when I stop»

**Description:**
The composer gets dictation. `desktop/ui/app.js`, `desktop/ui/index.html`, `desktop/ui/style.css`,
`desktop/ui/strings.en.json`, `specification/features/DESKTOP_VIEWS.md`, `tests/unit/test_desktop_static.py`.

**What needs to be done:**
- A mic button in the composer, shown when `features.dictation` is on and `/local/dictation` says available
  (otherwise absent, or disabled with the reason as its hint).
- Start and stop:
  - a click starts, a second click stops;
  - holding the button or ⌥Space for longer than a short moment talks while held and stops on release;
  - Esc cancels: the input goes back to what it was before the recording.
- The live words:
  - the interim phrase shows in a muted style in the composer as it is spoken (text only, never HTML);
  - each `final` is appended to the input's text, after anything already typed, and can be edited;
  - the text stays in the input after the stop; Enter sends it as usual.
- A level meter and a timer while listening; «recognizing…» between the stop and `done`; an `error` leaves the input
  as it was, with one readable line in the composer's notice.
- «Send when I stop»: a preference kept per window (like the other preferences, `localStorage`); when on, the line is
  sent as soon as `done` arrives (and not when the result is empty).
- Strings in English; her words are whatever the recognizer returns (Ukrainian by default).
- `DESKTOP_VIEWS.md`: a "Dictation (v4.7)" section and the phase row.

**Dependencies:** LUMI-333

**Expected result:**
In `Lili.app` the owner holds the mic button, speaks Ukrainian, sees the words appear, edits and sends.

**Acceptance criteria:**
- [ ] The button appears only when the server and the shell can dictate; click, hold and ⌥Space work; Esc cancels and
  restores the input.
- [ ] Interim text muted and replaced, finals appended after the typed text, never `innerHTML`.
- [ ] The level meter and the timer while listening; «recognizing…» after the stop; an error restores the input with
  one line.
- [ ] «Send when I stop» persists and sends by itself when the recording ends.
- [ ] **Tests:** static tests in `tests/unit/test_desktop_static.py` (the button, the strings English, no HTML for the
  live text, Esc, the preference); an end-to-end run in headless Chrome against the proxy with a fake shell
  dictation.
- [ ] **Gates:** `uv run ruff check .`, `uv run pytest -q`.
- [ ] **Manual (owner):** in `Lili.app` holding the mic button and speaking Ukrainian shows the words while speaking;
