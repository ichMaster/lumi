# v4.3 — Issues

Issues for phase **v4.3 — Journal and thoughts** (version **v4 — The window: her files, pictures, journal and
thoughts in Lili.app**), derived from the Tasks and DoD in [ROADMAP.md](../../ROADMAP.md) §v4.3, the concept
[DESKTOP_VIEWS.md](../../features/DESKTOP_VIEWS.md), the design handoff
[design/v4/handoff/](../../../design/v4/handoff/README.md) §7–§8 and the contracts in
[ARCHITECTURE.md](../../ARCHITECTURE.md). This file covers one phase; ids continue from the previous phase
(LUMI-308 → **LUMI-309…313**).

v4.3 lets the owner read two more things from the window:
- **her journal**, day by day: the code-owned stamp (mood, biorhythms, forecast) apart from her prose, then each
  `## HH:MM` section;
- **her whole thought stream**, newest first, paged back to the first thought, with filters by kind, spoken or silent,
  and a date jump.

It builds on v4.1 (the owner routes and their token rule, the view row, the right panels, the safe markdown
renderer), v4.2 (the paging cursor pattern), the v0.28 journal and the v0.12 thought stream. It leaves State, Schedule
and a turn's tools (v4.4) and every action (v4.5) to later phases.

**Reconciled against the code and the live data (2026-11-18):**
- **The journal layout on prod** (read-only structure counts over `~/lumi/prod/data/journal/owner/`, no entry text
  read out): 143 day files from 2026-06-16 to 2026-11-17, 239 `## HH:MM` sections, every file at most 7 KB.
  - 141 days carry the full stamp (`> **Настрій:**`, `> **Біоритми:**`, `> **Прогноз:**`).
  - 2026-06-16 has mood and biorhythms but no forecast, so each stamp field must be optional.
  - 2026-06-17 was written before the stamp existed: its heading is `# 17 червня`, not the date; it has no stamp and
    no `## HH:MM` section, and its prose holds other headings. The parser must open it as one untimed section.
  - Every biorhythm line parses as three cells `name ±0.00 (label)`; the labels seen are high, low, rising, falling
    and critical (`core/biorhythm.py` `_label`). The value is ASCII `+`/`-` from `format_biorhythms`; accept `−`
    (U+2212) too.
- **The thought stream on prod** (metadata counts only): 5,589 thoughts from 2026-06-10, all with `user_id: owner`,
  17 kinds, 325 spoken, `when` always `YYYY-MM-DDTHH:MM`, the list already in `when` order, the longest text
  4,284 characters. `when` has minute resolution, so it is not unique and cannot be the cursor on its own.
- **The thoughts live in memory.** Prod runs `state/sqlite_store.py`, which inherits the thought list from
  `JsonRepository` (`self._thoughts`, appended under the turn lock, never pruned: `prune_thoughts` has no caller).
  `Repository.thoughts_for(user_id, "")` returns a sorted **copy**, oldest first, filtered by the originating user —
  the surfacing filter the page must go through. Reading it needs no lock.
- **No role exists on the server.** `create_app` knows two tokens: the owner's client token and the room's. The
  resolved user is `core.user_id` (`core/user.py` `DEFAULT_USER_ID = "owner"`). The owner-only rule is therefore a
  small core function on the user id that the v6.2 accounts replace with the account's role; a server built for
  another user (a test with `user_id="ada"`) gets 403 from both journal routes.
- **When each view is served.** v4.1 set the rule "the views read what exists" (`features.files` is independent of
  `files.enabled`). The journal follows it: `features.journal` is true for the owner whenever a journal root is
  configured (it always is: `journal_dir` defaults to `<data root>/journal`), whether or not `journal.enabled` is on.
  The thoughts follow the existing view policy instead: `thoughts.show: off` already turns `/thoughts` off, so it
  turns the Thoughts view off too (`features.thoughts` false, the route 404).
- **`Core` has no journal root accessor.** `_journal_dir` and `_user_id` are private; `Core._journal()` builds the
  per-turn tool. LUMI-309 adds `Core.journal_root` like v4.1's `files_root` (never created by a read).
- **The proxy forwards exact paths only** (`desktop/proxy.py` `FORWARDED`, a set of `(method, path)`). The day route
  has its date in the path, so the proxy needs one narrow pattern for `/v1/journal/<YYYY-MM-DD>` (LUMI-312), and the
  proxy contract test that checks each forwarded route against the server must accept it.
- **One field the design needs beyond DESKTOP_VIEWS.** The Thoughts stream's day divider shows that day's count
  ("Today · Monday, 16 November · 11"), and a page of 100 can cut a day in two. The page therefore carries
  `days: {date: count}` for the dates on the page, counted over the filtered stream. DESKTOP_VIEWS and ARCHITECTURE
  gain it in LUMI-311.
- **The design strings are not merged yet.** `desktop/ui/strings.en.json` has `views.journal` and `views.thoughts`
  (v4.1 merged the view row), and `thoughtKinds` (the strip's kind captions) and the nine emotion captions. The 44
  `journal.*`, `thoughts.*` and `strip.open_thoughts` keys of `strings.en.add.json` come in with LUMI-312 and LUMI-313.
- **The renderer is there.** v4.1's reader renders markdown with DOM nodes only; a journal section's prose (and the
  2026-06-17 day's own headings) goes through the same renderer, never `innerHTML`.

## v4.3 — Journal and thoughts

### LUMI-309 — The journal reader in core: list the days, parse a day (stamp, sections), the owner-only rule

**Description:**
The read side of the v0.28 journal for the window, beside the tool in `core/journal.py`: list a user's days and parse
one day into its stamp and sections. Plus `Core.journal_root` and the owner-only rule (`core/user.py`).

**What needs to be done:**
- `core/journal.py`, pure, no model, never writing:
  - `parse_entry(date, text) -> {date, stamp, sections, markdown}`:
    - a first line starting with `# ` is the heading and is dropped (its text may be the date or anything else);
    - the **stamp** is the run of `> **Key:** value` lines before the first section: `Настрій` → `mood`, `Біоритми` →
      `biorhythms`, `Прогноз` → `forecast`. Any recognised key → a stamp object with the missing keys `null`; none →
      `stamp: null`. A blockquote line with another key stays in the prose;
    - `biorhythms` is a list of `{name, value, label}` parsed from the ` · `-separated cells `name ±0.00 (label)`
      (`+`, `-` or `−`); a line that doesn't parse into cells gives `null` (the raw stays in `markdown`);
    - **sections** split on lines that are exactly `## HH:MM`: `[{time, text}]`, each text trimmed. Non-blank text
      before the first timed section (after the heading and the stamp) becomes a first section with `time: null`; a
      day with no timed section is one untimed section. Other headings stay inside the prose;
    - `markdown` is the whole file as read;
    - never raises on content: a day that is only a heading gives `sections: []`.
  - `list_days(root) -> {days:[{date, sections, size, stamp}], truncated}`: the regular `YYYY-MM-DD.md` files that
    name a real date, newest first; `sections` and `stamp` (bool) from `parse_entry`; other names, folders, links out
    of the root and FIFOs ignored; at most 5,000 days (`truncated`). A missing root is an empty list.
  - `read_day(root, date) -> parse_entry(...)`: the date must be `YYYY-MM-DD` and a real date, else a 400-class
    error; the path through `safe_path`; missing → 404-class; over 256 KB → 413-class; read as UTF-8 with
    replacement. The errors reuse the v4.1 `core/browse.py` error kinds so the server maps them the same way.
- `Core.journal_root` (property): `journal_dir/<user_id>`, never created by a read.
- `core/user.py`: `may_read_journal(user_id) -> bool` — true only for the owner (`DEFAULT_USER_ID`). Its docstring
  says the journal is owner/admin-only by rule (ROADMAP §v9.6) and that the v6.2 accounts replace it with the
  account's role.

**Dependencies:** None

**Expected result:**
Any day of her journal, with or without a stamp, parses into its stamp and sections, and the day list reads newest
first, without writing anything.

**Acceptance criteria:**
- [ ] A full-stamp day parses: mood, three biorhythm cells (value, label), forecast, and its `## HH:MM` sections in
  order.
- [ ] The 2026-06-16 shape (no forecast) gives `forecast: null`; the 2026-06-17 shape (a non-date heading, no stamp,
  no timed section, inner headings) gives `stamp: null` and one untimed section holding the prose with its headings.
- [ ] Prose before the first timed section becomes an untimed first section; an unparseable biorhythm line gives
  `biorhythms: null`; a heading-only day gives `sections: []`.
- [ ] `list_days` is newest first, ignores other files, folders and links out of the root, counts sections and the
  stamp, caps at 5,000; a missing root is empty.
- [ ] `read_day`: a malformed date, an impossible date (`2026-02-30`), `..` or an absolute path → 400-class; missing
  → 404-class; over 256 KB → 413-class.
- [ ] `may_read_journal("owner")` is true; any other id is false.
- [ ] **Tests:** `tests/unit/test_journal_reader.py` — fixtures built from the prod shapes above (synthetic text, no
  real entry), the list, the errors, and the journal folder's fingerprint unchanged after every call. No model.
- [ ] **Gates:** `uv run ruff check .`, `uv run pytest -q`.

### LUMI-310 — The thought page in core: newest first, a stable cursor, kind / spoken / date filters, the totals

**Description:**
One page of her thought stream for the window: a pure function in `core/thoughts.py` over the list
`thoughts_for(user_id, "")` returns, and `Core.thoughts_page` that feeds it this user's surfaceable thoughts only.

**What needs to be done:**
- `core/thoughts.py`: `thought_page(thoughts, *, before=None, limit=100, kinds=(), spoken=None, date=None) -> dict`
  over a list oldest first (as `thoughts_for` returns it):
  - **the cursor** is opaque (base64url JSON, like v4.2's) and holds a position in that list counted from the oldest
    end, so thoughts appended meanwhile never shift it; `next` is the cursor of the oldest item returned, `null` when
    nothing older matches;
  - `limit` 1..100; `kinds` any number of directive names (empty = all); `spoken` `true` / `false` / `None`;
  - `date` (`YYYY-MM-DD`, used only when `before` is absent) starts the page at the newest thought on or before that
    day's end;
  - `items:[{when, kind, text, emotion, spoken}]`, newest first; `seeds` and `user_id` never leave; a text longer
    than 10,000 characters is cut with `…`;
  - `stats:{total, per_day, spoken_share}` over the stream filtered by `kinds` and `spoken` (not by the page):
    `per_day` is `total` over the days from the user's first to last thought, inclusive, one decimal;
    `spoken_share` is spoken / total (0 when empty);
  - `days:{date: count}` for each date on the page, counted over the same filtered stream;
  - `kinds:[…]` — the distinct kinds in the user's whole stream, most frequent first;
  - a malformed cursor, a bad `limit`, or a bad `date` → `ValueError` (the server's 400).
- `Core.thoughts_page(**filters)`: `thought_page(self._repo.thoughts_for(self._user_id, ""), **filters)` — never
  the raw `thoughts_since`, never the turn lock, no model call.

**Dependencies:** None

**Expected result:**
The whole stream pages from the newest thought back to the first, under any mix of filters, and a thought sparked
with another user never appears.

**Acceptance criteria:**
- [ ] Paging with `next` from the newest page reaches the first thought: every thought exactly once, newest first,
  including thoughts with the same `when`.
- [ ] A thought appended between two page requests doesn't shift or repeat the older pages.
- [ ] `kinds` (several at once), `spoken` and `date` filter correctly, alone and together; `days` and `stats` match
  the filtered stream.
- [ ] A malformed or foreign cursor, `limit` 0 or 101, and `2026-13-01` are refused.
- [ ] `Core.thoughts_page` returns only the core user's thoughts: a store holding thoughts of `owner` and `ada` gives
  each core only its own (the surfacing filter), and no item carries `seeds` or `user_id`.
- [ ] **Tests:** `tests/unit/test_thought_page.py` — plain `Thought` lists and a `JsonRepository` with two users; no
  model.
- [ ] **Gates:** `uv run ruff check .`, `uv run pytest -q`.
