## Findings

### 1. 🟠 MEDIUM — The guard reads the text between two English apostrophes as a quote

**Where:** `tests/contract/test_english_interface.py` `QUOTED` (the `'[^'\n]*'` alternative) and `_prose_left`.

**Failure scenario:** someone writes `# the turn's tail — тут обрізано — doesn't matter`. The single-quote
alternative pairs the apostrophe of `turn's` with the one of `doesn't`, takes «s tail — тут обрізано — doesn» as a
quote and removes it, so `_prose_left` returns `None` and the guard passes. `# Lili's mood is тихий, isn't it` passes
the same way. English possessives and contractions are common in this code's comments, so the guard misses exactly
the mixed comments it exists to catch. A stray `"` (an inch mark, an unmatched quote) in a docstring shifts the
double-quote pairing in the same way, because that alternative may span lines.

**Fix:** a single quote counts as a quote only when it is not inside a word (`(?<!\w)'[^'\n]*'(?!\w)`), and a
double quote never spans a line. Quotes of her text in «…» may still span lines.

**Test:** the two comments above are caught; a quoted Ukrainian word in `'…'`, `"…"`, `«…»` and backticks is still
allowed; every comment and docstring in the code still passes.

### 2. 🟡 LOW — The terminal client's status line shows her style key raw

**Where:** `tui/app.py` `_status_text` (`style: {core.style}`); `desktop/ui/strings.en.json` `styles`.

**Failure scenario:** after she picks a style, the terminal client's status line reads its key raw, e.g.
`style: коротко (Lili)`. The window maps the key to an English name, but its map (`desktop/ui/strings.en.json`
`styles`) holds only the twelve base styles, so a meta-style such as «лагідна» or «блискавична» reaches the window raw
as well: "лагідна (Lili)". The key is her prompt's word, but on this line it is interface.

**Fix (later):** one map of every palette key (the base styles and the meta-styles) to an English name that both
clients read, and the terminal client renders `core.style` through it. Home: backlog.
