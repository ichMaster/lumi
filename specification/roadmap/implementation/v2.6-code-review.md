## Findings

### 1. 🟠 The Telegram daemons die on SIGTERM — `telegram/inbound.py:155`, `telegram/outbound.py:325`

**Scenario:** `systemctl --user stop lumi-server@dev` stops the daemons too (`PartOf`). Both handle only Ctrl+C
(`except KeyboardInterrupt` → "stopped", the bot session closed); SIGTERM's default kills them. Seen live on the box
(2026-10-20 00:17:55): `Main process exited, status=143`, `Failed with result 'exit-code'` for both units, no
"stopped" line. Every server stop, restart or reboot leaves two red units (the v2.9 panel would show them as
crashes), and outbound killed between a send and `fifo.save_pointer` resends that reply on the next start.

**Fix:** stop on SIGTERM exactly as on Ctrl+C — one shared helper installs `signal.default_int_handler` for SIGTERM;
the server's `term_as_interrupt` and both daemons use it before their loop. Exit 0, "stopped" logged, the session
closed, the unit `inactive`.

### 2. 🟠 `./lumi-cli serve` loses the refusal message — `cli/main.py:79`

**Scenario:** v2.6 turned the server's configuration refusals into `ConfigRefusal` (a `SystemExit` with code 78, so
systemd doesn't restart-loop), and prints the message only in `server/__main__.py`'s `if __name__ == "__main__"`
block. `./lumi-cli serve` calls `server.__main__.main()` directly: the refusal reaches the top as `SystemExit(78)`
and Python exits with no output — "LUMI_SERVER_TOKEN is not set" or "Port 8766 … already in use" is never shown.
Before v2.6 the CLI printed it.

**Fix:** one entry point, `server.__main__.run()`, that runs `main()` and turns a `ConfigRefusal` into the printed
message + exit 78; the module's `__main__` block and `cli serve` both call it.

### 3. 🟠 The viewer portrait doesn't follow a remote server — `tui/app.py` (no `turn` handler), `core/agent.py:1120`

**Scenario:** the core writes `face.txt` into its own data root — on the box, which has no display. The server
pushes `turn {emotion, intensity, theme}`, but the TUI client doesn't act on it, so the Mac viewer never changes. On
dev it's an inconvenience; at the **v2.7** move it would take her portrait away from prod.

**Defer → v2.7:** the client writing a local `face.txt` from the pushed `turn` event is small, but it is a
behavior the owner hasn't decided on yet (proposed 2026-10-19). It must land before the prod move. The full face in
the window stays v2.11.

### 4. 🟠 A turn can hang ~8 minutes behind a slow model — `core/llm.py` (the Gemini stream → blocking fallback)

**Scenario:** with `gemini-3.1-pro-preview` degraded (2026-10-17/19), a streamed tool-loop turn times out at 120 s,
falls back to a blocking call with a 120 s timeout and two retries: up to ~8 minutes, during which the client's
input (`/model` included) waits in the queue. Pre-existing (not v2.6 code), but a remote server makes it the
everyday path.

**Defer → v2.7 (before the prod move):** bound the whole turn (one deadline across the stream, the fallback and the
retries), and let a command bypass the turn queue. A design change in `core/llm.py`, not a v2.6 fix.

### 5. 🟡 A bracketed IPv6 host passes the guard but not uvicorn — `server/__main__.py` (`bind_problem`, `bind_error`)

**Scenario:** `LUMI_SERVER_HOST=[::1]` → the guard and the port check strip the brackets and pass; `serve()` hands
`[::1]` to uvicorn, whose bind fails — after the core (and its startup calls) ran.

**Defer → backlog:** normalize the host once in `main()` (strip the brackets) for every use. Nobody binds IPv6 today.

### 6. 🟡 An older server without `features` — `tui/remote.py` (`RemoteCore.features`)

**Scenario:** a v2.6 client against a v2.5 server reads `features` as all-off and refuses `/image` / `/web` the server
could serve. Client and server ship together (one repo, one tag), so the skew is rare.

**Defer → backlog:** fall back to the client's own flags when the state carries no `features`.

### 7. 🟡 Loose refusal wording — `server/__main__.py` (`bind_problem`)

**Scenario:** `169.254.1.1` or `::ffff:192.168.1.5` is refused as "a public address". The refusal is right (neither
is a LAN/Tailscale bind); the word isn't.

**Defer → backlog:** say "not a LAN or Tailscale address".

## What's solid

- **The bind guard runs first** — after the token, before the env guard, the data root and the core; wildcard,
  public and hostname binds are refused with the fix named; an address not up yet is retried, a taken port is not.
- **`systemctl stop` closes her session** — proven on the box (4.2 s, exit 0, "session closed") and by a
  real-process test that fails without the fix.
- **The client reads the server only through the API** — pinned by a contract test that checks itself (a deliberate
  read is caught).
- **The API grew additively** (`features`, `timing`, 503 while stopping) with ARCHITECTURE and the contract test
  in the same commits; in-process output is byte-identical (pinned).
- **Secrets:** no token in a unit, a log or an error line; the box's `.env` was written `0600` without a temporary
  copy.

## Fixes applied

### #1 — the Telegram daemons stop like Ctrl+C (68066cf)

- **Change:** a shared `core/stopsignal.py` — `sigterm_as_interrupt()` makes SIGTERM raise `KeyboardInterrupt` in
  the main thread. Both daemons' `run()` call it before `asyncio.run(_main())`, so `systemctl stop` takes their
  existing Ctrl+C path ("stopped" logged, the bot session closed, exit 0); the server's `term_as_interrupt` uses
  the same helper.
- **Regression tests:** `tests/integration/test_daemon_sigterm.py` — a real child process running the daemons' stop
  pattern gets a real SIGTERM → exit 0, "stopped", the `finally` ran; a source pin that both daemons install the
  helper before their loop (**fails without the fix** — checked).
- **Verified live on the box** (2026-10-20 00:27, the dev checkout at 74948f8): `systemctl --user stop
  lumi-server@dev` → the server and both daemons `inactive` (no `failed`), `outbound stopped` logged; `start` →
  all three active.

### #2 — `./lumi-cli serve` prints its refusal (74948f8)

- **Change:** `server.__main__.run()` — the one entry point for `python -m server` and `./lumi-cli serve` — runs
  `main()` and turns a `ConfigRefusal` into the printed message + exit 78.
- **Regression tests:** `tests/unit/test_cli.py::test_serve_says_why_it_refuses_instead_of_exiting_silently`
  (no token → exit 78 + the message on stderr) and `tests/unit/test_server_main.py::test_run_prints_a_refusal_then_exits_78`
  (a wildcard bind) — both **fail without the fix** (checked).

## Architecture impact

- A shared process helper, `core/stopsignal.py`: every long-running Lumi process under systemd (the server, the
  Telegram daemons) stops on SIGTERM exactly as on Ctrl+C. ARCHITECTURE §Deployment already states the server's
  behavior ("`systemctl stop` shuts the server down like Ctrl+C"); the daemons now match it. No API or data
  contract changed.
