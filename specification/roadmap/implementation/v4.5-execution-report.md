## Detailed Results

### LUMI-321: The write side in core

**Status:** completed
**Commit:** 7907002
**Files changed:** `core/actions.py` (added), `tests/unit/test_actions.py` (added).

- `upload` writes a new file under a free name (`rain (2).png`), opened with `"xb"`, so nothing is ever overwritten.
  - Pictures are typed by magic bytes, up to 10 MB.
  - NUL-free UTF-8 text is allowed up to 1 MB.
  - Anything else is refused (`NotServed`).
- `rename` stays within the entry's folder and never lands on a taken name (`Conflict`).
- `trash` moves into `.trash/<YYYY-MM-DD>/` under a free name; `restore` moves an item back to the place the log
  names. Nothing is ever deleted.
- Every path goes through `safe_path`. An entry that is itself a link is never moved, and the sandbox root is never
  moved.
- `ActionLog` writes `<data root>/actions.jsonl`, one line per action, holding `{ts, action, path, to, size, client}`
  only. `original_of` finds where a trashed item came from.

**Validation:** unit tests pass (the rest of the sandbox byte-identical after each action); ruff clean.

### LUMI-323: The proxy

**Status:** completed
**Commit:** f9b8358
**Files changed:** `desktop/proxy.py`, `tests/_desktop_world.py`, `tests/contract/test_desktop_contract.py`,
`tests/integration/test_desktop_proxy_flow.py`.

- The five routes are forwarded. The upload's body cap is 10 MB plus a margin.
- A refused body is drained (up to 64 MB), so the page gets the 413 instead of a reset connection.

**Validation:** proxy contract and integration tests pass; ruff clean.
