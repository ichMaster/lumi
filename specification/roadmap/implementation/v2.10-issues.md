# v2.10 — Issues

Issues for phase **v2.10 — The admin panel: watch** (version **v2 — Client/server split: her brain on the server,
the TUI a thin client**), derived from the Tasks and DoD in [ROADMAP.md](../../ROADMAP.md) §v2.10, the design in
[ADMIN_PANEL.md](../../features/ADMIN_PANEL.md) §v2.10 and the contracts in [ARCHITECTURE.md](../../ARCHITECTURE.md).
This file covers one phase; ids continue from the previous phase (LUMI-251 → **LUMI-252…258**).

One web panel on the box, `lumi-admin`, shows **prod and dev side by side**: health checks with history, uptime,
tokens/cost/latency from the ledgers, logs. It can start, stop and restart their containers, and prod actions
need a typed confirmation. It never runs the core, never writes a data root and makes no paid call. Editing
settings from the panel is v2.11.

**Grounded in the real code (2026-11-10):**
- **Ledgers.** Both box instances write `cache-log.jsonl` (one row per model call: `ts`, `kind`, `model`, `input`,
  `output`, `cache_read`, `cache_write`, `latency_ms`, `pre_ms`, `post_ms`, `session_id`, …; on because
  `store.cache_monitor` is set) and `usage-ledger.jsonl` (one row per closed session).
- **Prices.** Today they live in `core/usage.py` `PRICING` / `pricing_for`.
- **Bus pointers.** `telegram/monitor.py` `queue_status` already computes the pointer lag (`inbox.pos`,
  `outbox.sent`).
- **Mood.** The daily reading is appended to `mood.log` as `===== <date> =====` blocks; `core/mood.py`
  `reading_is_complete` is the pure completeness test.
- **Scheduler and marker.** `schedule.state` holds the last firing per row; `env-marker` names the instance.
- **The server.** `GET /v1/health` is open; `GET /v1/state` needs the instance's `server.token`, which lives in its
  `secrets.yaml`.
- **The box.** Docker socket `root:docker 0660`, docker gid 999; port 8767 is free; `sudo` needs a password, so the
  ufw rule is the owner's.
- **The pattern.** matrix-agora's panel on the same box (`panel/`: FastAPI + static `index.html`/`app.js`,
  `group_add` the docker gid, LAN-only publish, its own token).

### LUMI-253 — The admin readers: read-only views of a data root and of the box

**Description:**
Pure readers over one instance folder (`<root>/settings.yaml`, `<root>/data/…`), opened **read-only**, and over the
box (`/proc`, disk). They return plain data for the API and the checks. Touches `admin/__init__.py`,
`admin/readers.py` (new), tests with fixture data roots.

**What needs to be done:**
- **Usage** from `cache-log.jsonl`:
  - tokens (input / output / cache read / cache write) and the estimated cost (`core.usage.pricing_for`) per day,
    per model and per kind;
  - the cache hit ratio;
  - turn latency (the `reply` kind) median and p95, with the PRE / MODEL / POST split where recorded;
  - the N slowest calls;
  - turns today and the last turn's age.

  Sessions per day come from `usage-ledger.jsonl`. Only the last D days are read (a cap), and a malformed line is
  skipped.
- **Errors** from `lumi.log`:
  - `ERROR` lines in the last 24 h;
  - model failures and timeouts (`lumi.llm` WARNING/ERROR) in the last hour;
  - a tail with a level filter and a text filter over `lumi.log` and the two Telegram logs.

  Reads are bounded: only the end of a large file. Every secret value of the instance (from its `secrets.yaml`) is
  replaced with `•••` in any returned line.
- **Mood:** today's `mood.log` block, its theme, and whether it is complete (`core.mood.reading_is_complete`).
- **Scheduler:** whether it is enabled (`scheduler.enabled` in `settings.yaml`) and the newest firing in
  `schedule.state`.
- **Bus:** inbox / outbox pending, via `telegram.monitor.queue_status`.
- **Instance:** the `env-marker`; the data-root size (walked, cached for 10 min).
- **Box:** uptime (`/proc/uptime`), load (`/proc/loadavg`), memory (`/proc/meminfo`), disk free under the roots.
  A missing source → `None`, never an exception.
- **The server token** for `/v1/state` is read from the instance's `secrets.yaml` and only handed to the HTTP
  client. It is never part of any returned structure.

**Dependencies:** LUMI-252

**Expected result:**
Given a data-root folder, the readers return its usage, latency, errors, mood, scheduler, bus and size as plain
data, without opening anything for writing.

**Acceptance criteria:**
- [ ] Aggregates over fixture `cache-log.jsonl` / `usage-ledger.jsonl`: tokens, cost, cache ratio, median / p95,
      slowest calls, turns today — exact values asserted.
- [ ] The 24 h error count, the model-failure count and a filtered tail over a fixture `lumi.log`; a secret value
      planted in a log line comes back as `•••`.
- [ ] Mood complete / incomplete / missing for today; scheduler newest firing; bus pending; marker; size.
- [ ] Every reader runs over a fixture root that is then fingerprinted unchanged; missing files → `None`.
- [ ] **Tests:** `tests/unit/test_admin_readers.py` — fixture roots under `tmp_path`, injected clock, no network.
- [ ] **Gates:** `uv run ruff check .` + `uv run pytest -q` green.

### LUMI-254 — The health checks + the every-minute runner with a `health.jsonl` history

**Description:**
Named checks per instance, each `green` / `amber` / `red` (or `off` when the feature is off), computed from the
readers and two HTTP probes, **no paid call**. A runner evaluates them every minute and appends a bounded
`health.jsonl` history. Touches `admin/health.py` (new), tests.

**What needs to be done:**
- **The checks:**

  | Check | Red / amber / green |
  |---|---|
  | `server` | `GET /v1/health` answers as this instance; red when down, amber when slow (> 2 s) |
  | `state` | `GET /v1/state` with the instance's token answers |
  | `mood` | today's reading is complete; amber when missing before noon, red when incomplete |
  | `model` | the last successful call is recent while the server runs; red when the last hour has repeated failures or timeouts |
  | `telegram` | both daemon containers running, and the inbox / outbox pending under a threshold |
  | `scheduler` | the newest firing is recent; `off` when the scheduler is off |
  | `disk` | free space: amber < 10 %, red < 5 % |
  | `marker` | the env marker equals the instance name |

  Thresholds are named constants. Each check is a pure function `(facts, now) → CheckResult(name, status,
  detail)`.
- **The runner:** every 60 s (the clock and the HTTP client injected), all instances. It appends one row per
  instance per run to `health.jsonl` in the admin's own folder (rotated at a size cap). It keeps the last N results
  per check in memory for the UI's history strip.
- **The probe:** "probe the model now" is **not** in this phase's checks — a later opt-in, as ADMIN_PANEL says.
  Only the ledgers judge the model.

**Dependencies:** LUMI-253

**Expected result:**
A stopped dev server turns its `server` and `state` checks red on the next run (within a minute), and green again
after it starts.

**Acceptance criteria:**
- [ ] Each check green / amber / red / off over fixture facts (table-driven).
- [ ] The runner over a fake HTTP client + fixture roots: a "server down" fake turns `server` red; restored → green;
      `health.jsonl` rows appended, rotated at the cap.
- [ ] No check calls a model or any paid API (the HTTP fake records every URL; only `/v1/health` and `/v1/state`
      appear).
- [ ] **Tests:** `tests/unit/test_admin_health.py`; injected clock, no network.
- [ ] **Gates:** `uv run ruff check .` + `uv run pytest -q` green.

### LUMI-255 — The container seam: status / start / stop / restart / logs — the Docker API, a fake in tests

**Description:**
A `ContainerRunner` protocol per instance and service, and its one real implementation: the Docker Engine API over
`/var/run/docker.sock` (stdlib `http.client` over a unix socket — no new dependency). Containers are found by their
compose labels (`com.docker.compose.project=lumi-<i>`, `…service=<s>`), never by a name built from a request. A fake
runner backs the tests. Touches `admin/containers.py` (new), tests.

**What needs to be done:**
- `list(instance)` → per service:
  - `state` (running / restarting / stopped / missing / unknown);
  - `started_at`, uptime;
  - `restart_count`;
  - the image tag (`io.lumi.build` label).
- `start` / `stop` / `restart(instance, service)`:
  - only for the three known services (`server`, `telegram-inbound`, `telegram-outbound`);
  - `stop` uses the compose grace (300 s), so her session closes.
- `logs(instance, service, tail)`: the multiplexed stream decoded and capped.
- Docker unreachable → `unknown`, never an exception to the caller.
- **The prod rule** (pure): an action on `prod` needs `confirm == "prod"` in the request; anything else is refused
  with what to type. Dev needs none.

**Dependencies:** None

**Expected result:**
The panel can see and drive each instance's three containers by label, and a prod action without the typed
confirmation never reaches Docker.

**Acceptance criteria:**
- [ ] The Docker client over a fake unix-socket server (fixture JSON for `/containers/json` and inspect, the 8-byte
      log framing): list, start / stop / restart calls with the right method and path, logs decoded.
- [ ] A service outside the three, or an unknown instance → refused; never a request to Docker.
- [ ] The prod rule: no confirmation / a wrong word → refused; `prod` → allowed; dev needs none.
- [ ] **Tests:** `tests/unit/test_admin_containers.py`; no real Docker, no network.
- [ ] **Gates:** `uv run ruff check .` + `uv run pytest -q` green.

### LUMI-256 — The admin app: FastAPI JSON API + the static UI, the registry, the admin token

**Description:**
`python -m admin` serves a FastAPI JSON API and a static page (the matrix-agora panel pattern: no bundler, no node,
charts as inline SVG). It reads the instance registry and its own token, and ties the readers, checks and container
seam together. Touches `admin/app.py`, `admin/__main__.py`, `admin/registry.py`,
`admin/static/{index.html,app.js,panel.css}` (new), tests, `specification/ARCHITECTURE.md`.

**What needs to be done:**
- **The registry, `admin.yaml`** (in the admin's folder, `LUMI_ADMIN_HOME`): each instance's name, root (its folder,
  mounted read-only), server URL and compose project. **Only prod and dev.** It is validated at start, with readable
  errors.
- **The admin token** lives in the admin folder's `secrets.yaml` (`admin.token`, `0600`):
  - The panel refuses to start without one, or with one shorter than 32 characters.
  - Every `/api/*` route requires `Authorization: Bearer <token>`. Only `/` (the static page) and `/healthz` are
    open.
  - The page asks for the token once and keeps it in `sessionStorage`.
- **The bind guard:** `server.__main__.bind_problem` (LAN / Tailscale / loopback only; the wildcard only inside the
  image).
- **The API:**

  | Route | Returns / does |
  |---|---|
  | `GET /api/overview` | per instance: up/down, version, image tag, uptime + restarts, model + profile, mood + theme + complete, session + turns today, last turn age, 24 h errors, data-root size; the box |
  | `GET /api/health` | the checks + their history |
  | `GET /api/services` | the containers |
  | `POST /api/services/{instance}/{service}/{action}` | `{confirm?}` — the prod rule |
  | `GET /api/usage?instance=&days=` | per day / model / kind, cache ratio, latency, slowest |
  | `GET /api/logs?instance=&source=&level=&q=&tail=` | log lines, secrets redacted |

  The health runner starts with the app (a background task).
- **The UI:** an instance switcher (prod always red), tabs Overview / Health / Services / Usage / Logs. Inline-SVG
  bars for tokens and cost per day; a confirmation prompt that asks for `prod` before a prod action.
- **Contracts (pinned):** the token on every `/api` route; no write path into a data root; no secret in any
  response.

**Dependencies:** LUMI-253, LUMI-254, LUMI-255

**Expected result:**
Run against two fixture instances and a fake runner, the panel's API shows both side by side, a dev container can
be started, and a prod restart is refused until confirmed.

**Acceptance criteria:**
- [ ] **Integration** (`tests/integration/test_admin_api.py`): FastAPI `TestClient`, a fake container runner, two
      fixture instances, a fake HTTP client for the servers. Overview / health / services / usage / logs answer for
      both; a stopped dev container is started; a prod restart without `confirm` is a 409 naming what to type, and
      with it the runner's restart is called.
- [ ] **Contract** (`tests/contract/test_admin_contract.py`):
  - every `/api` route answers 401 without the token or with a wrong one;
  - every route is called over fixture roots, which are fingerprinted unchanged (no write into a data root);
  - known secret values (the instance `secrets.yaml`, planted into a log line) appear in no response body.
- [ ] A missing or short admin token refuses to start; an invalid `admin.yaml` refuses, naming the key.
- [ ] **Contract:** ARCHITECTURE gains §Admin panel (v2.10): the separation (never the core, never a data-root
      write, no paid call), the token, the Docker API seam, the three contracts above.
- [ ] **Gates:** `uv run ruff check .` + `uv run pytest -q` green.
- [ ] **Manual (owner):** the browser UI (LUMI-258).
