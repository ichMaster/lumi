## Fixes applied during execution

- **Every chat line paid a command round-trip** (LUMI-213 pilot test): the client sent each line to
  `/v1/command` first, so a failing command call also blocked the turn — only `/` lines reach the layer now.
- **A false "server stopped"** (live smoke): `pgrep -f "python -m server"` is case-sensitive, but macOS shows
  the framework interpreter as `…/Python -m server` — smoke stops are now verified by PID.
- **The server banner was buffered** under redirected stdout → `flush=True`; a shutdown log line added.
- **A rejected token got a "start the server" hint** → `ServerAuthError` with the right hint.

## Architecture impact

- **The command layer** is the new seam for every client (TUI now, pywebview v2.8): ARCHITECTURE §Contracts.
- **Server API v1** in ARCHITECTURE §Contracts, pinned by `tests/contract/test_server_api_contract.py`.
- The feared cost of the owner's decision (command output changing in the in-process TUI) did **not**
  materialize: the semantic kinds preserve the exact look.

## Found, for the review

- **No lock on a data root** — `./lumi` (in-process) and `./lumi-server` on the same instance would be two
  brains writing one memory; only documented so far.
- **A command typed during a turn is queued silently** — it runs after the turn (a 55 s live turn made it
  look broken); pre-existing v1.2 behavior.
