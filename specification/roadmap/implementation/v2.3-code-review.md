## Findings

### 1. 🟠 `end_session` races an in-flight turn at shutdown

**Anchor:** `server/__main__.py` (`finally: core.end_session(app.state.service.session)`).
**Scenario:** a turn is streaming; the owner presses Ctrl+C twice (uvicorn's force exit). The request task
is cancelled, but the turn's runner thread keeps running inside `core.reply` (it holds the service lock to
the end — by design, so a disconnect never half-finishes a turn). `uvicorn.run` returns and the `finally`
immediately runs `end_session` on the main thread: summarizing and closing the session while the runner is
still appending the turn's messages and post-turn state — two threads in a core that isn't built for it.
A graceful single Ctrl+C is safe (uvicorn waits for the stream, which ends with the turn); v2.2's blocking
turns had the same exposure on a force exit, v2.3's runner threads make it the normal case.
**Fix:** close the session only after taking the service lock — wait (bounded) for an in-flight turn to
finish; if it doesn't within the bound, skip `end_session` with a log line rather than racing it.

### 2–4. Deferred

- **2 (backlog):** `queue.get(timeout=…)` + SSE `:` keepalive comments in the generator would give the event
  loop a cancellation point (and a heartbeat for future proxies). The owner chose to skip it for now.
- **3 (backlog):** the streamed loop could hand its accumulated `contents` (with the tool results) to the
  blocking loop instead of restarting; with the 400 trigger fixed, fallbacks are rare.
- **4 (backlog):** store the text with the record and reject a reused id with different text (409).

## What's solid

- **Never twice:** a retry by `turn_id` on either route returns the stored outcome — proven with fault
  transports (drop / garbled frame / no `done`) and a client disconnect mid-turn: exactly one server turn.
- **The lock can't leak:** the runner owns it for the whole turn and releases it in `finally`, whatever the
  client does.
- **The emotion contract holds:** deltas are prose only; the emotion arrives in `done`, validated on
  completion (a malformed mock reply → `calm`).
- **The TUI didn't change** — `RemoteCore` honours the v1.4 callbacks; real TCP shows incremental deltas.
- **The Gemini fix is bounded:** at most one extra forced-final round, only when an answer came back empty;
  the regression tests fail on the old code.
