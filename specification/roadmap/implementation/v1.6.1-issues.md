### LUMI-196 — `Core.prompt_snapshot()`: the assembled system prompt without a turn

**Description:**
The probe needs Лілі's **real** assembled system prompt (canon + memory blocks + facts + mood — what
the reply call would carry) as the realtime session's `instructions` — but today the assembly runs
only inside `reply()` (`_system_prompt` is private; `last_prompt` exists only after a turn). Add a
small **public** `Core.prompt_snapshot(session) -> str`: assemble and return the current system
prompt exactly as a reply turn would see it (without RAG's per-message recall block — there is no
incoming message), **without** calling the model and **without** persisting anything.

**What needs to be done:**
- `Core.prompt_snapshot(session)` — a thin public wrapper over the existing `_system_prompt` path
  (ensure mood/day summaries as `reply()` does; no recall/fact-recall blocks — no query exists).
- No side effects beyond the same lazy ensures `reply()` already runs (mood once per day etc.).
- Unit tests with `MockLLMClient`: the snapshot contains the canon + the memory sections; two calls
  are stable; nothing is persisted to messages; no reply-model call is made.

**Dependencies:** none.

**Expected result:**
`core.prompt_snapshot(session)` returns the same system prompt a turn would carry — the probe (and
later v1.6.3's `session.update`) reuses the one prompt builder instead of duplicating it.

**Acceptance criteria:**
- [ ] Snapshot contains the canon and the injected memory/mood sections (unit, mock).
- [ ] No model call, no message persisted, no store mutation beyond the daily ensures.
- [ ] Stable across repeated calls in one session.
- [ ] **No paid calls** in tests.

### LUMI-197 — `scripts/realtime_probe.py`: mic ↔ Realtime ↔ speaker, pure context

**Description:**
The probe itself, the `gemini_probe` pattern: a standalone **manual, paid, never-CI** script that
connects to the GA Realtime API (`wss://…/v1/realtime?model=gpt-realtime-2.1-mini`), configures the
session (instructions = the LUMI-196 snapshot; voice from `LUMI_REALTIME_VOICE`, set before first
audio; `semantic_vad`; pcm16 @ 24 kHz in/out), streams microphone audio up and plays reply audio
back — a live spoken conversation with Лілі's persona. **No tools, no classifier, no persistence.**
Headphones assumed (no AEC). The script prints, per turn: the user transcript, the assistant
transcript, and the **latency stamps** (speech-stop → first audio delta; turn totals) — the numbers
LUMI-198 records.

**What needs to be done:**
- WebSocket client (asyncio `websockets`; new optional extra, e.g. `realtime` — keep the core deps
  untouched) with the standard `OPENAI_API_KEY` header; model/voice/VAD from env
  (`LUMI_REALTIME_MODEL` default `gpt-realtime-2.1-mini`, `LUMI_REALTIME_VOICE`).
- Audio: `sounddevice` (the dictation extra) — mic InputStream → base64 pcm16 append events;
  speaker OutputStream ← response audio deltas; `LUMI_STT_DEVICE` respected for the mic.
- The event loop: session.update (instructions + voice + VAD) → print session.created/updated;
  handle input transcription events, response audio deltas + transcript deltas, VAD interrupts
  (barge-in: stop local playback); Ctrl+C closes cleanly.
- **Latency stamps**: wall-clock from VAD speech-stop to the first audio delta, per turn + a
  session summary at exit (median/min/max) — printed, ready to paste into VOICE_MODE.md.
- **Pure, unit-tested helpers** (no network/audio in tests): the session-config builder (given
  env → the session.update payload), the event dispatcher (scripted event dicts → the right
  callbacks + latency math), pcm chunk base64 framing. The live `run()` is glue (`# pragma: no
  cover`, like the voicer's).
- The script reads the snapshot via `build_core(...)` + `prompt_snapshot()` (read-only store
  access; the running TUI should be closed — note it in the header docstring).

**Dependencies:** **LUMI-196** (the snapshot).

**Expected result:**
`OPENAI_API_KEY=… uv run --extra realtime python scripts/realtime_probe.py` → a live spoken
conversation with Лілі (her persona, her memory context), turn-by-turn transcripts and latency
numbers in the terminal.

**Acceptance criteria:**
- [ ] Session-config builder: env → correct session.update payload (instructions/voice/VAD/formats) — unit.
- [ ] Event dispatcher: scripted events → transcript callbacks, latency stamps computed correctly, barge-in stops playback — unit, no network.
- [ ] The audio path uses `sounddevice` with `LUMI_STT_DEVICE` honored; pcm16@24k both ways.
- [ ] **Manual + paid, never CI** — no test opens a socket or touches audio hardware.
- [ ] No tools, no classifier, no writes to the store (read-only snapshot).

### LUMI-198 — The live run: findings back into the spec + docs

**Description:**
The probe's whole point — run it live (the owner does the talking), then **record what reality
said** into [VOICE_MODE.md](../../features/VOICE_MODE.md) as a "Probe result" note (the v1.3
LUMI-184 pattern): measured **first-audio latency** (median/min/max over ~10 turns), whether the
**persona survives** in speech (Ukrainian, her tone, the canon taboos), observed **event shapes**
(the exact event types v1.6.2's adapter must handle), and any surprises (VAD behavior, barge-in
feel, voice quality per `LUMI_REALTIME_VOICE` option). Plus the operator docs.

**What needs to be done:**
- A **Probe result** section in VOICE_MODE.md §7 under v1.6.1: the latency table, the persona
  verdict, the event-shape list, the chosen voice; date-stamped (the LUMI-184 verdict pattern).
- `.env.example`: the `OPENAI_API_KEY` + `LUMI_REALTIME_MODEL`/`LUMI_REALTIME_VOICE` block with the
  probe how-to (`uv run --extra realtime python scripts/realtime_probe.py`; headphones note).
- ROADMAP §v1.6.1 marked with the verdict one-liner (GO / adjust) for v1.6.2 to build on.

**Dependencies:** **LUMI-197** (the probe), plus one live paid session run by the owner.

**Expected result:**
VOICE_MODE.md carries measured reality (latency + events + persona verdict); v1.6.2 starts from
facts, not the docs' assumptions.

**Acceptance criteria:**
- [ ] VOICE_MODE.md "Probe result (v1.6.1)" — latency numbers, event shapes, persona verdict, date.
- [ ] `.env.example` covers the realtime probe vars + how-to.
- [ ] ROADMAP v1.6.1 carries the verdict; **the probe itself stays manual + paid, never CI**.
