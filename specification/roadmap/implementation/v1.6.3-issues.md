## LUMI-203: The first-clause cut — earlier first audio on multi-clause replies

### Description

The probes measured ~0.3–0.65 s of the felt first-audio latency sitting in the wait for the FULL
first sentence before TTS starts. The first spoken chunk of a turn should start at a clause
boundary instead; later chunks stay whole sentences (prosody suffers least where it matters least
— the opening word groups sound natural cut at a comma).

### What needs to be done

- `voice/stream_tts.py`: the `SentenceAssembler` (or a thin wrapper used only by the pipeline)
  gains a **first-chunk mode**: until the first chunk of a turn has been emitted, a clause
  boundary — a comma/dash/semicolon followed by whitespace — or a ~N-word threshold
  (`LUMI_VOICE_FIRST_CLAUSE_WORDS`, default 8; `0` → off, exact current behavior) also flushes.
  Never mid-word; a minimum-length guard (a 1–2-word fragment reads badly — hold until it clears);
  after the first emission the turn reverts to whole-sentence splitting; `finish_turn()` resets
  the mode for the next turn.
- The cut applies only to the SPOKEN stream (the pipeline) — the TUI text render is untouched.
- Config: `Config.voice_first_clause_words` + `.env.example`.

### Dependencies

None.

### Expected result

On a multi-clause first sentence, her first audio starts noticeably earlier; short replies sound
exactly as before.

### Acceptance criteria

- [ ] First chunk flushes at a clause boundary / the word threshold; never mid-word; min-length guard pinned
- [ ] Later chunks are whole sentences; the next turn starts fresh (finish_turn resets)
- [ ] `LUMI_VOICE_FIRST_CLAUSE_WORDS=0` → byte-identical splitting (pinned)
- [ ] `pytest` + `ruff` pass; no paid CI

## LUMI-204: Emotion-colored delivery — her voice carries the turn's state

### Description

The talking register synthesizes every sentence NEUTRAL today (`voice_settings_for(None)`), while
the old v0.14 outbox voicer already colors delivery by emotion. Her live voice should carry her
state — calm steadier, playful livelier — presentation only, never the text (EMOTION.md §9).

### What needs to be done

- `voice/stream_tts.py`: the `SpeechPipeline` takes an **emotion supplier** (a callable returning
  the current emotion name or None) and passes its value into `tts.stream(..., emotion=…)` per
  sentence — `voice_settings_for` (shared with the v0.14 voicer) does the mapping.
- TUI wiring: the supplier reads the core's last validated emotion (`Core.last_emotion`) — so the
  PREVIOUS turn's state colors the stream while the new one is still generating, and the new state
  takes over from the moment it validates (the natural continuity: she is still in the mood she
  was in when she started speaking).
- Unit tests: the mock TTS records the emotion per sentence; a mid-turn state change shows the
  handover; None degrades to the neutral middle (unchanged behavior).

### Dependencies

None.

### Expected result

An audible difference between a calm and a playful Лілі in voice mode, with zero text changes.

### Acceptance criteria

- [ ] The pipeline plumbs the supplied emotion into every synth call (mock-pinned)
- [ ] TUI supplies the last validated emotion; None → the neutral middle
- [ ] No contract/text change; `pytest` + `ruff` pass; no paid CI

## LUMI-205: Deepgram WS resilience — auto-reconnect with backoff

### Description

Any Deepgram socket close/error today tears voice mode down to text immediately. Long sessions
(and flaky Wi-Fi) need the connection to heal in place: reconnect with backoff, keep the mic
open, and only degrade to text after the retries exhaust.

### What needs to be done

- `voice/live.py` (+ the TUI's `_voice_pump`): on a socket close/error, attempt
  `LUMI_VOICE_RECONNECT` (default 3) reconnects with exponential backoff (~1/2/4 s): re-open the
  `DeepgramStream` (a fresh `UtteranceTracker` — a half-utterance across a drop is unrecoverable
  and must not corrupt the next one), surface a dim readable note («voice: reconnecting 1/3…»),
  resume pumping events. The mic stream stays open throughout (frames sent into a dead socket are
  dropped by the sender guard, never an exception storm).
- Success → a dim «voice: reconnected» note, the session continues; all retries exhausted → the
  existing readable degrade to text (unchanged).
- Config: `Config.voice_reconnect` + `.env.example`.
- Tests: a scripted connector that fails N times then succeeds — the loop recovers, the tracker is
  fresh, the notes fire once each; exhausted retries → the degrade path.

### Dependencies

None.

### Expected result

A transient network blip pauses voice for a few seconds and heals; only a real outage drops the
session to text.

### Acceptance criteria

- [ ] Reconnect with backoff (default 3 attempts), fresh tracker per reconnect, mic uninterrupted
- [ ] Readable notes: reconnecting / reconnected / degraded (each once)
- [ ] Exhausted retries → the existing text degrade (unchanged wording)
- [ ] `pytest` + `ruff` pass; scripted transport only, no network in tests

## LUMI-206: Voice observability — the stage line, /latency, Gemini prices in usage

### Description

The probes printed a per-turn stage breakdown (`endpoint → llm first → tts first`); the product
lost it. And the usage ledger prices Gemini calls at zero — voice turns (all-Gemini) cost nothing
on `/usage`, which hides the real cost of the always-on voice mode.

### What needs to be done

- **The stage line:** the voice path stamps three moments per spoken turn — utterance commit
  (VoiceLoop), the first reply delta (the TUI's on_delta), the first audio chunk fed to the
  speaker buffer (SpeechPipeline) — and the TUI prints one dim line per voice turn:
  `voice: endpoint 0.7s · llm first 0.9s · tts first 0.3s`. Off by default?— no: always on in
  voice mode (one dim line per turn, the probes proved the value).
- **`/latency`:** a voice section — the session's median/min/max of those stages (present only
  when voice turns happened).
- **Gemini prices in `core/usage.py`:** the current table (per 1M tokens): `gemini-3.1-pro`
  $2/$12 · `gemini-2.5-flash` $0.30/$2.50 · `gemini-2.5-flash-lite` $0.10/$0.40 — matched by
  model-id prefix like the existing entries, so text AND voice turns on the gemini profile cost
  correctly in the ledger and `/usage`.
- Tests: the stage stamps assemble into the line (fake clock), the /latency voice section
  renders/omits correctly, the pricing rows resolve by prefix.

### Dependencies

None.

### Expected result

Every spoken turn shows where its time went; `/usage` shows what voice mode actually costs.

### Acceptance criteria

- [ ] A dim per-turn stage line in voice mode (endpoint / llm first / tts first)
- [ ] `/latency` gains the voice section (only when voice turns exist)
- [ ] Gemini models priced in `core/usage.py` (prefix-matched; pinned by test)
- [ ] `pytest` + `ruff` pass; no paid CI
