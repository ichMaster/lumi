# v4.6 — Issues

Issues for phase **v4.6 — Her voice in the window** (version **v4 — The window: her files, pictures, journal and
thoughts in Lili.app**), derived from the Tasks and DoD in [ROADMAP.md](../../ROADMAP.md) §v4.6 (the owner, 2026-11-19)
and the contracts in [ARCHITECTURE.md](../../ARCHITECTURE.md). This file covers one phase; ids continue from the
previous phase (LUMI-326 → **LUMI-327…330**).

v4.6 moves the making of her voice to the server:
- each of her lines is voiced **once**, after the reply is shown, while one switch is on;
- the window plays it with a ▶ on the line;
- Telegram sends the same file instead of calling ElevenLabs again;
- one «Voice» toggle in the window turns it on or off for both, and survives a restart.

It builds on the v0.14 TTS adapter (`voice/tts.py`), the v2.7.1 voice tags (`speech`), the v2.5 server outbox and
event bus, the v0.13 outbound daemon, and the window's key-guarded binary relay (v4.1–v4.5). It leaves dictation in
the window to v4.7.

**Reconciled against the code (2026-11-19):**
- **The TTS seam:** `voice/tts.py`:
  - `TTS.synth(text, *, emotion) -> bytes`;
  - `ElevenLabsTTS(api_key, voice_id, model)` applies `speakable(model, text)`, so a tag only reaches a model that
    performs it, and the per-emotion `voice_settings_for(emotion)`;
  - `MockTTS` records its calls.
  
  The server reuses this seam unchanged.
- **Her line's text for the voice:**
  - `Core.last_speech` is the reply with her voice tags (v2.7.1). `state/bus.py` `mirror_reply(outbox, state,
    speech)` puts it on the outbox record as `speech`.
  - The outbound daemon voices `rec.get("speech") or rec["text"]`.
  - A spoken thought and a Telegram turn go through `Core.reply`, so they carry `last_speech` too.
  - A shown thought (`mirror_thought`) has no `speech`.
- **Who writes the outbox:** the server, through `_Service.mirror(write, *args)`, best-effort and under the lock. The
  callers are:
  - `_run_turn`: a client turn, your line first when the bridge mirrors it;
  - `server/brain.py` `_inbox_turn` (a Telegram or dictated line);
  - `_spoken_turn` (a nudge or a graduated thought);
  - `_run_scheduled` (a shown thought, when `scheduler.show_to_outbox`).
  
  The outbox exists only when `bridge.enabled` or `voice.enabled` (`outbox_of`). `state/fifo.py` `append` reads the
  last id and then appends, so two threads appending at once could share an id. A second writer thread needs one
  lock around it.
- **Today's Telegram voice** is fixed for the daemon's lifetime:
  - `telegram.voice` (`cfg.telegram_voice`) picks the loop at start: a voice loop of one message per reply, synthesized
    by the daemon, or the text loop in N-batches;
  - a photo record (`photo`) always goes as a photo;
  - the daemon refuses to start in voice mode without `ELEVENLABS_API_KEY` + `LUMI_VOICE_ID`.
- **Her lines carry no id.** `Message` (`core/repository.py`) has none.
  - The `message` push is `{role, text, source, emotion, intensity, pictures?, origin}`, with an SSE id `<boot>-<seq>`.
  - The window shows its own turn from the response, and the `message` push only for lines from elsewhere
    (`origin`).
  - The voice therefore needs an id of its own (32 hex) that rides on the outcome and on the `message` push, while
    the switch is on.
- **Replays:** `_REPLAYABLE = ("message", "thought")`, last `REPLAY_MAX = 50`. A replayed line that names a voice
  needs its `voice` event replayed too, or it would wait for its ▶ forever.
- **The data root:** paths are derived in `server/__main__.py`, e.g. `thumbs_dir_of(cfg)` and `actions_log_of(cfg)`.
  The voice files follow that pattern (`<data root>/voice/<user_id>/`, outside her sandbox).
- **The proxy** (`desktop/proxy.py`):
  - forwards exact `(method, path)` pairs from `FORWARDED`, plus `FORWARDED_PATTERNS` such as `/v1/journal/<date>`;
  - relays a body as bytes, with the key added there.
  
  The audio route is a pattern route of the same kind.
- **No usage ledger for ElevenLabs exists** (`core/usage.py` is the model's tokens). One request per line is shown by:
  - the server's log, one line per generation;
  - the daemon's log, which never synthesizes for a record that has a file;
  - the ElevenLabs dashboard's history.

## v4.6 — Her voice in the window

### LUMI-327 — The voice of her lines on the server: the switch, the store, the ordered job, the 30-day expiry

**Description:**
A server-side voice module, `server/voice.py`, with four parts:
- **the switch:** `<data root>/voice.json`;
- **the store:** `<data root>/voice/<user_id>/<id>.mp3`;
- **one ordered worker:** it voices each of her lines once, off the turn's critical path, and then writes her outbox
  record with the file's name;
- **the bounded 30-day expiry.**

`server/app.py` `_Service` and `server/brain.py` route her lines through it. The routes and pushes come in LUMI-328.

**What needs to be done:**
- **The switch** (`VoiceSwitch`):
  - `enabled` is persisted in `<data root>/voice.json` as `{"enabled": bool}`, written atomically. When the file is
    missing, the first value is `telegram.voice`. An unreadable file is logged and falls back to that first value.
  - `available` is true only with `ELEVENLABS_API_KEY` and `voice.voice_id` set.
  - `active = enabled and available`. Setting it while unavailable is refused (`VoiceUnavailable`) and nothing is
    written.
- **The store** (`VoiceStore`):
  - files live at `<data root>/voice/<user_id>/<id>.mp3`, where `<id>` is 32 lowercase hex (`uuid4().hex`);
  - `path_for(user_id, id)` refuses any id that doesn't match;
  - a file is written through a temp file and a rename, so a reader never sees half a file;
  - the store is outside her sandbox, and her file tools never see it.
- **The voice job** (`LineVoicer`): one worker thread and one FIFO queue, lazily started and drained at shutdown.
  - **While the switch is active**, each of her lines gets an id, assigned when the line is shown:
    - a client turn, a Telegram turn, a nudge, a graduated thought;
    - a shown thought mirrored to the outbox (`mirror_thought`), so Telegram keeps voicing it as today.
  - **For each line, the worker:**
    1. synthesizes `speech or text`, capped at `VOICE_MAX_CHARS` (the ElevenLabs request limit, cut at a sentence or
       space boundary), with the validated emotion (`TTS.synth(text, emotion=...)`);
    2. stores the file;
    3. appends her outbox record with `voice: "<id>.mp3"`, if an outbox exists;
    4. reports `(id, ready=True)` to a callback, which becomes the `voice` push in LUMI-328.
  - **A failed generation:**
    - the exception is logged, and the text never;
    - no file is made, and any partial temp file is removed;
    - the record goes with `voice: null`, and the callback gets `ready=False`;
    - the turn is never touched.
  - **One log line per generation:** `voice: made <id> (<n> chars, <ms> ms)` or `voice: failed <id>`. The line holds no
    text and no key.
  - **While the switch is off:** no id, no generation. Her record goes with `voice: null`.
  - **Every server-written `kind="lili"` record now carries the `voice` key** (a name or `null`). A record that lacks
    the key is "old" for the daemon (LUMI-329).
  - **Photo records** (`send_image`) are unchanged and never voiced.
- **The outbox keeps the order of the lines.**
  - While a line is being voiced, the outbox writes after it (your next mirrored line, her next line) wait in the
    same queue, so Telegram never gets them out of order.
  - Appends from the worker and from the turn thread are serialized by one lock, so no two records share an id.
  - Without an outbox (no bridge, no voicer), the job still makes the file for the window.
- **The 30-day expiry** (`expire(now)`):
  - removes `*.mp3` files under `<data root>/voice/` whose mtime is older than 30 days, plus stray temp files;
  - bounded per pass (e.g. 500 files), so a large backlog is cleared over several passes;
  - never follows a link and never leaves the voice folder.
  - It runs at server start and once a day on the brain's beat; the wiring is in LUMI-328.
- **Wiring the callers:** `_run_turn`, `_inbox_turn`, `_spoken_turn` and `_run_scheduled` go through one service
  method that does the mirror and the voice for her line, in place of the direct `mirror(mirror_reply, …)`.
  - The returned id is available to the caller for the outcome and the `message` push (LUMI-328).
  - The room's path (`_room_turn`, the Agora space) is never touched, so the room's lines are never voiced.
- The TUI's `/voice`, the local voicer (v0.14) and `state/bus.py`'s in-process writers are unchanged.

**Dependencies:** None

**Expected result:**
While the switch is on, each of her lines is voiced once, in order, after it is shown, into
`<data root>/voice/<user_id>/<id>.mp3`. Her outbox record then names that file, or carries `voice: null` when the
switch is off or the generation failed.

**Acceptance criteria:**
- [ ] The switch persists in `voice.json`, its first value is `telegram.voice`, `available` needs the key and the
      voice id, and setting it while unavailable is refused.
- [ ] One generation per line, whatever the number of clients; `speech` is preferred to `text`; the validated
      emotion is passed; the text is capped.
- [ ] A failed generation leaves no file, writes the record with `voice: null`, reports `ready=False` and never fails
      the turn.
- [ ] Outbox records keep the order of the lines while a line is being voiced, and no two records share an id.
- [ ] With the switch off, no TTS call is made and every her-record carries `voice: null`.
- [ ] The expiry removes only voice files older than 30 days, is bounded per pass, and never leaves the voice folder.
- [ ] **Tests:** unit tests in `tests/unit/test_server_voice.py`, with `MockTTS`, an injected clock and a temp data
      root (no network, no paid call):
      - the switch (first value, persistence, unavailable);
      - one generation per line, `speech` and emotion used, the cap;
      - a failure → no file and `voice: null`;
      - the outbox order with a slow TTS;
      - the 30-day expiry and its bound;
      - an id that isn't 32 hex refused.
- [ ] **Gates:** `uv run ruff check .`, `uv run pytest -q`.

### LUMI-328 — The routes and pushes: `GET /v1/voice/<id>`, `POST /v1/voice`, `voice` on the state, the outcome and the `message` push, the `voice` push

**Description:**
The server API for her voice in `server/app.py` (additive, API v1), with the wiring in `server/__main__.py`:

- the switch;
- the store;
- the expiry at start and daily.

ARCHITECTURE §Contracts gets a "v4.6 (additive)" paragraph, and `docs/SERVER_SETUP.md` its section. Contract tests
pin it.

**What needs to be done:**
- **`GET /v1/voice/{id}`:**
  - owner-only: the room's token gets 403, no token 401;
  - `id` must be 32 hex, otherwise 404 (never a path);
  - the file of the resolved `user_id` is served as `audio/mpeg` with `X-Content-Type-Options: nosniff` and
    `Cache-Control: private, max-age=86400`;
  - a missing or expired file is 404;
  - it never takes the turn lock.
- **`POST /v1/voice {enabled: bool}`:**
  - owner-only;
  - persists the switch and returns `{enabled, available}`;
  - while unavailable, it answers 409 `voice unavailable: no ElevenLabs key or voice id` and changes nothing;
  - it pushes the new `state`, and never takes the turn lock.
- **`GET /v1/state`** gains `voice: {enabled, available}`, where `enabled` reports `active`.
- **While the switch is active:**
  - her line's outcome (`/v1/turn`, the stream's final event) carries `voice: "<id>"`, and so does her `message` push;
  - when the job finishes, a `voice` push `{message: "<id>", ready: bool}` follows her `message`;

- **With the switch off**, the outcome and the `message` push are byte-identical to v4.5 (no `voice` key).
- **`server/__main__.py` builds:**
  - `ElevenLabsTTS(cfg.elevenlabs_api_key, cfg.voice_id, cfg.voice_model)` when both are set, otherwise no TTS
    (`available: false`);
  - the switch from `<data root>/voice.json` with the first value `cfg.telegram_voice`;
  - the store under `<data root>/voice/`;
  - the job, drained at shutdown.
  
  The expiry runs once at start and on the brain's daily beat; when no brain is hosted, a small daily timer runs it.
- **The room never reaches any of this.** The Agora routes and the room's turn are unchanged.
- **ARCHITECTURE §Contracts "v4.6 (additive)":**
  - the two routes;
  - `voice` on the state, the outcome and the `message` push (only while on);
  - the `voice` push;
  - the outbox record's `voice` field (a name or `null`; absent on a pre-v4.6 or in-process record);
  - `voice.json`, the store and the 30-day expiry;
  - "one generation per line, made only while on".
- **`docs/SERVER_SETUP.md`:** the switch, where the files live, what turns it off.

**Dependencies:** LUMI-327

**Expected result:**
A client sees `voice: {enabled, available}` in the state, can turn the switch, and gets `voice` ids on her lines with
a `voice` push when each audio is ready, fetchable from `GET /v1/voice/<id>`. Nothing changes while the switch is
off.

**Acceptance criteria:**
- [ ] `GET /v1/voice/<id>`: auth (401 / the room's 403), `audio/mpeg`, `nosniff`, a missing id and a non-hex id give
      404.
- [ ] `POST /v1/voice`: auth, the room's 403, persists across a new app on the same data root, and gives 409 while

- [ ] `voice` on the state; the `voice` push after `message`, replayed on reconnect.
- [ ] The outcome and the `message` push are unchanged with the switch off.
- [ ] The room's lines are never voiced (a room turn makes no TTS call).
- [ ] **Tests:** contract tests in `tests/contract/test_server_api_contract.py`, with `MockTTS` injected (no network):

      - the push order (`message` then `voice`) for a client turn and a Telegram turn;

- [ ] **Contract:** ARCHITECTURE §Contracts "v4.6 (additive)", pinned by the contract tests above.

### LUMI-329 — Telegram sends the stored file: a record with `voice`, without it, and an old record

**Description:**
`telegram/outbound.py` decides per record instead of per daemon. A record with `voice` sends that stored MP3 as a
voice message, converted to OGG/Opus, and never calls ElevenLabs. A record with `voice: null` goes as text. A record
without the key, from before v4.6 or written by the in-process TUI, goes the old way. `docs/TELEGRAM_SETUP.md` is
updated.

**What needs to be done:**
- **One loop for every record.** In FIFO order, from the pointer:
  - **a photo record** goes as a photo (unchanged);
  - **a `kind="lili"` record with `voice: "<id>.mp3"`:**
    - the name must be 32 hex + `.mp3`;
    - the daemon reads `<data root>/voice/<user_id>/<name>` and converts it with `mp3_to_ogg`;
    - it sends `send_voice(ogg, caption)`, on its own (never batched);
    - **it never calls TTS.**
    - If the file is missing or unreadable, the record degrades to text with a warning, and the loop never wedges.
  - **a record with `voice: null`, or a `kind="user"` line:** text, N-batched as today (`batches`, `render`, `chunk`,
    the face photo by `telegram.photo`);
  - **a `kind="lili"` record without the `voice` key** (old or in-process): voiced by the daemon's own TTS when
    `telegram.voice` is on and the key + voice id are set (the old way), otherwise text.
- **Each voiced record stands alone.** A record with a file and an old record voiced by the daemon break the text
  batch, like a photo record; the text records around them batch as before.
- **A send failure** leaves the pointer before the record and retries on the next loop, as today.
- **The daemon starts** in every case.
  - The old "voice mode needs the key" exit becomes a warning: old records then go as text.
  - The daemon builds a TTS only for old records.
- **Logs:** `sent the stored voice id=<n>`, and for an old record `voiced the old way id=<n>`. Never the text, never
  the key.
- **`docs/TELEGRAM_SETUP.md`:**
  - the voice now comes from the server's switch (the window's «Voice» toggle, `POST /v1/voice`);
  - `telegram.voice` is its first value;
  - what an old record does;
  - how to check that one request is made per line.

**Dependencies:** LUMI-327

**Expected result:**
Telegram gets her voice from the server's file, with no second ElevenLabs call. With the switch off it gets text, and
nothing in flight at the upgrade is lost.

**Acceptance criteria:**
- [ ] A record with a file goes as a voice message, and the mock TTS is never called for it.
- [ ] A record with `voice: null` goes as text (batched); a missing file degrades to text.
- [ ] An old record is voiced the old way when `telegram.voice` is on, and goes as text otherwise.
- [ ] Order and the pointer: voiced records stand alone, text batches around them, and a failure retries without
      skipping.
- [ ] A name that isn't 32 hex + `.mp3` is never read (text instead).
- [ ] **Tests:** unit tests in `tests/unit/test_telegram_outbound.py` (or the existing outbound test module), with a
      fake bot, `MockTTS` and a fake `to_ogg`, no network:
      - the three cases;
      - the mixed order;
      - a missing file;
      - a bad name;
      - a send failure leaving the pointer.
- [ ] **Gates:** `uv run ruff check .`, `uv run pytest -q`.

### LUMI-330 — The window: the proxy's two routes, ▶ / ❚❚ on her lines, one player at a time, the «Voice» toggle

- **`specification/features/DESKTOP_VIEWS.md`:** a "Her voice (v4.6)" section and the phase row.

- [ ] **Tests:**
      - `tests/contract/test_desktop_contract.py`: the two routes, their key, the binary relay of `audio/mpeg`;
      - `tests/unit/test_desktop_static.py`: the button and the toggle built without HTML, the strings in English, no
        `autoplay` / `.play()` outside a click handler, one player at a time.
- [ ] **Gates:** `uv run ruff check .`, `uv run pytest -q`.
- [ ] **Manual (owner):** on dev and then on prod:
      - a reply plays in the window, and the same voice arrives in Telegram;
      - the switch works in both directions: off → no ▶ and text in Telegram, on → the next line is voiced;

## v4.6 scope notes

**Critical path:** LUMI-327 → LUMI-328 → LUMI-330 (LUMI-329 beside LUMI-328).

  Telegram as a voice message, and ElevenLabs was called once for it.
- With the switch off, no audio is made, the window shows no ▶, and Telegram gets text. Switching back on voices the
  next line.
- The switch survives a server restart. Without a key it is disabled and says why.
- A failed generation leaves the text everywhere and the turn unchanged.
