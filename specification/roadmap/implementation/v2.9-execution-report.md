## Detailed Results

### LUMI-244: The settings schema + the loader (#244)

**Commit:** 492799b
**Files:** `core/settings.py` (new), `core/config.py`, `core/agent.py`, `core/envguard.py`, `core/llm.py`,
`telegram/{__init__,inbound,outbound,check}.py`, `server/__main__.py`, `tui/__main__.py`, `cli/main.py`,
`pyproject.toml`, `uv.lock`, `tests/conftest.py`, `tests/unit/test_settings_loader.py` (new),
`specification/ARCHITECTURE.md`.

- One schema of **217 settings in 27 groups** (YAML key, env alias, type of 11, default, description, `secret`,
  `restart`, choices/min/max, old names) + an `ENV_ONLY` exemption list (image-baked, compose parameters,
  `LUMI_SETTINGS_DIR`, the probe-only names).
- `resolve()`: default < `.env` (deprecated, warned) < `settings.yaml` / `secrets.yaml` < the process environment.
  A wrong value in a file refuses (a `SystemExit`) naming the file, key, value and allowed values; a secret's value
  shows as `(hidden)`; a misplaced secret is refused; an unknown key only warns.
- `load_config` reads the merged env-string values through its **unchanged parsers** (217 `os.getenv` → `_get`).
- **Deviation:** the file values are exported into `os.environ` without overriding a real variable (what
  `load_dotenv` did) — the probes, the SDK defaults and the direct readers relied on it; exported values are
  tracked so a later resolve never mistakes them for the real environment.
- Consumers: the Gemini key reaches image gen / web lookup from the config; the Telegram daemons take
  `cfg.log_level`; the env guard honours `cfg.allow_dirty_prod`; messages name `secrets.yaml`.
- Live check: the dev tree's real `.env` gave a `Config` identical in every field to the pre-v2.9 path.
