### LUMI-234: The bounded turn (#234)

**Status:** completed · **Commit:** 3ff5dba

`core/llm.py`: `TURN_DEADLINE_S = 180` across the stream, the blocking fallback and the retries of one turn — each
request's timeout is what is left; no retry or fallback starts once it is spent; the turn ends with
`TurnDeadlineExceeded` (an `LLMError` → the server's readable 502 / the unavailable line). The budget is
**thread-local** (a background thought keeps its own) and re-entrant. `_call_with_retries` gained an optional
deadline (unchanged without it). **Reconciled with the code:** the issue's "a slash command is never queued behind
a turn" is not what the server does (one request at a time, by design since v2.2); ROADMAP and ARCHITECTURE now say
a line typed meanwhile waits **at most the deadline**.

**Validation:** 6 tests over a fake clock (no real wait, no network): the streamed turn ends at 180 s, not ~480 s;
the blocking retries stop at the deadline; a fast model is unaffected; a thought on another thread keeps its budget;
the retry helper never retries past a deadline; the server answers the readable 502.

### LUMI-235: The deploy agent (#235)

**Status:** completed · **Commits:** a95ad1d, 5fde10c (the follow-up below)

`scripts/deploy_agent.py` — stdlib-only (the box's system Python 3.10 runs it), pure decisions (`ci_verdict`,
`release_tags`, `dev_action`, `prod_action`, `errors_since`, `smoke_verdict`) + an `Agent` over an injected runner /
HTTP / clock; commands `tick`, `confirm <tag>`, `status`, `rollback dev|prod`, `install`; state + log in
`~/lumi/deploy/`, a flock against overlapping steps. `deploy/systemd/lumi-deploy.service` (oneshot, runs the
agent's own copy) + `lumi-deploy.timer` (5 min).

- **dev** deploys a `main` commit whose check runs are all green **and which contains what dev runs** — an addition
  to the issue, so the old `main` (88+ commits behind `v2-dev` before the merge) could never be deployed.
- **prod** deploys the newest `vA.B.C` only when exactly that tag is confirmed; never an older tag.
- **The smoke** (no model call): `/v1/health` as the instance and the expected version, `/v1/state` with the
  instance token (never logged), the enabled units still active 60 s later, no new `ERROR` in `lumi.log` since the
  restart. A failure rolls back and marks the ref bad; a manual rollback sticks.
- **Follow-up 5fde10c (owner decision 2026-10-20, asked before the install):** a prod deploy first stops prod's
  server and archives `data/` beside it (`backups/data-<YYYYmmdd-HHMM>-<running tag>.tar.gz`, the `prod_update.py`
  naming); a failed archive deploys nothing, restarts prod and clears the confirmation (no stop every 5 minutes).
  Also: the error scan starts after the restart (the old server's shutdown lines don't count), and a command that
  times out is a failure, not a crash.

**Validation:** 34 agent tests over fixtures and a fake world (git / uv / systemctl / GitHub / the servers) — no
network, no systemd, no paid API; the contract test (a full deploy + rollback leaves `data/` and `.env`
byte-identical, the agent writes only `deploy/` and `prod/backups/`); the unit tests extended to the deploy
units. Loaded on the box's Python 3.10.12 (compiled in memory); the real GitHub check-runs API returns the parsed
shape.
