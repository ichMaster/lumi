## Findings

### 1 · 🟠 The Services result vanishes
`admin/static/app.js` `act()`:
- it writes the result (or `refused: …`) into `#act-result`, then `setTimeout(renderServices, 1500)` re-renders the
  card and the line is gone;
- `prompt()` → Cancel returns `null`, and the function returns silently.

**Scenario (live, 2026-11-11):** the owner restarted prod from the browser. No restart event reached Docker, the
page showed nothing lasting, and the owner believed it had happened.

**Fix:** keep the last action's outcome in the page state and render it after every refresh, with the time;
say "cancelled — nothing sent" on a cancelled prompt; show a refusal in red.

### 2 · 🟠 Retries counted as model failures
`admin/readers.py` `errors()` counts every `lumi.llm` WARNING/ERROR in the last hour. Prod's log has:

| Count | Line | What it is |
|---|---|---|
| 154 | `returned no answer … asking once more` | a retry |
| 50 | `… forcing the …` | a retry |
| 27 | `tool-loop streaming failed → blocking loop` | a fallback that answered |
| 35 | `returned no answer again` | a real failure |
| — | ERROR lines | a real failure |

**Scenario:** the `model` check turns amber / red on a recovering Gemini; the signal stops meaning "she can't
answer".

**Fix:**
- `model_failures_1h` counts only `lumi.llm` ERROR lines and the `… again` warnings;
- a new `model_retries_1h` counts the rest;
- the check stays green on retries alone and names them in its detail.

### 3 · 🟡 The ufw line in the admin section
**Fix:** say the publish address (LAN only) is the fence and that Docker publishes past ufw (as §1 explains). The
ufw rule only keeps the box's own rules consistent.

### 4 · 🟡 A panel action during a deploy's smoke (deferred)
`scripts/deploy_agent.py` checks each container's id and restart count across the stable minute. A panel restart in
that minute makes the agent roll a good release back. The panel doesn't see the agent's `agent.lock` (it doesn't
mount `~/lumi/deploy`).

**Home: v2.11.** Its apply + restart flow has to coordinate with the agent anyway (mount the lock read-only and
refuse while it is held).

### 5 · 🟡 Re-reading the logs (deferred)
Bounded (4 MB, the tail) and cheap on the box today (load ~1.3 on 4 cores), but it scales with open pages.

**Home: backlog.** Cache the parsed tail per file by size + mtime.

## What's solid

- **The token:**
  - every `/api` route sits behind `hmac.compare_digest`;
  - no cookie → no CSRF; no CORS headers, so a cross-origin page can't read responses or send the header;
  - the contract test enumerates the routes, so a new one can't skip it.
- **Path inputs:** the log `source` is an allowlist, instances come from the registry, the static mount is
  Starlette's (no traversal).
- **The containers:** found by compose labels, only three services × three actions; the prod rule is enforced
  server-side and proven against a fake daemon.
- **Secrets:**
  - the `/v1/state` view is whitelisted, and every log line returned is redacted;
  - the admin token is never in an instance's data;
  - no secret is in any response (contract).
- **Writes:** the instance folders are mounted read-only (verified live: `touch` → Read-only file system), and the
  readers open nothing for writing (fingerprint tests).
- **The UI** renders data with `textContent` only (pinned).
